# 設計の記録 ── サービスサイト ＋ 顧客サイト共用

自社のサービスサイトと、顧客に納品するサイトを**同じコードベースで作る**ための一式です。
自社サイトが標準仕様の1号案件になり、そのまま顧客サイトのテンプレート資産になります。

サイトの主張は1つに絞ってあります。**「いまのホームページは借地権、紬がつくるのは所有権」**。
ページの並び・図・章題・OGPの文面は、すべてこの一文を支えるために配置されています
（→「主張の設計」）。

デザインは **NOT A HOTEL デザインガイドライン v2.0** に準拠しています（→「デザインの出所」）。

```
npm run tokens               # styles/design.tokens.json → styles/tokens.css を生成
npm run og                   # OGP画像とファビコンを生成（文面を変えたときだけ）
npm run build                # out/ に静的HTMLを出力（トークンの同期も検査する）
npm run verify               # 標準仕様の自動検証（ブラウザ実測を含む）
npm run verify -- --static   # 静的検証のみ（ブラウザ不要・CI向け）
npm run verify -- --write    # LCP実測値を src/data/config.ts に書き戻す
```

---

## なぜこの形にしたか

設計書の最大のリスクは、**20項目の標準仕様が文書のまま運用されないこと**でした。
そこで仕様を実行可能な検証スクリプト（`verify`）にして、**FAILが1件でもあれば納品しない**
というゲートにしています。`/spec` ページに載せている実測値は、この検証が出した数字です。

もうひとつの狙いは工数です。ベーシック6ページ198,000円が成立するのは
**5人日で作れるようになってから**なので、1号目から共通部分を資産化する必要がありました。
2件目以降は `src/data/config.ts` とページ本文（`src/pages/`）を差し替えるだけで、実装はほぼ再利用できます。

## 主張の設計

サイト全体で言うことは1つです。

> いま制作会社に作ってもらっているホームページは、土地でいえば**借地権**にあたる。
> 紬がつくるのは、お客様が**所有権**を持てるホームページ。

この主張を、気分の話で終わらせないために**4つに分解して、それぞれ検証できる形**にしています。
`owned.html` が主張の本体で、他のページはその材料です。

| 所有の中身 | 何をもって所有と言えるか | どこで確かめられるか |
|---|---|---|
| **① 住所** ドメイン | 初日からお客様の名義で取得する | ドメインの公開登録簿 |
| **② 建物** ソースコード | 一式を納品し、利用・改変・移管を制限しない | 契約書（`terms.html`）・`source.html` |
| **③ 地盤** 置き場所 | 実行時JSが0バイトなので、どのサーバーにも置ける | `verify` の「実行時JSなし」 |
| **④ 家具** 写真と原稿 | 撮影の元データを用途の制限なく渡す | 契約書（`terms.html`） |

**あえて自分の喩えを弱めている箇所があります。**
借地借家法には更新拒絶の正当事由（6条）と建物買取請求権（13条）があるので、
**本物の借地のほうが月額制のホームページ契約よりずっと守られています。**
`owned.html` はそれを表で認めたうえで、「いまの契約はむしろ定期借地（更地返還）に近い」と続けます。
都合の悪い事実を先に出したほうが、残りの主張が通ります。
なお法律の話には「弁護士ではない／契約書が優先」の断りを必ず添えています。

図 `land_vs_own` は、この主張の視覚版です。**左右の建物をわざと同じ見た目にしてあります。**
違いは土地の名義と、解約したあとに手元に残るものだけ、というのが図の主張だからです。

検証にも入れてあります。`verify` の **26「主張の一貫性」**が、
トップと `owned.html` の両方に「借地・所有・名義・ソースコード」が揃っていることを検査し、
片方だけの言い回しになったら落ちます。

## 値付けの設計（月額制への答え）

競合調査の結果は `claude/competitor-propagate.md`。要点は2つ。
**納品物がサイト作成ツールで、渡せるソースコードが存在しない。**
**36か月未満で解約するとサイトが非公開になる**と料金ページに明記されている。

### 相手の土俵から降りる
月額制の強さは「月いくら」で比べさせる点にある。同じ土俵で値下げ合戦をすると、
**ビルド原価がほぼゼロの相手には勝てない。** そこで比べる軸を2つに変えた。

1. **36か月の総額**（相手自身が譲渡の区切りに置いている期間）
2. **サイトがお客様のものになる時点**

数字は `src/data/prices.ts` の `compareRows()` が計算する。手で書かない。
図 `ownership_clock` は2の視覚版で、**同じ「36」を並べて意味が正反対だと見せる**。

### 入口を下げて、上で回収する
| | 入口 | 回収 |
|---|---|---|
| 月額制 | 制作費0円・初期5,000円 | 月額を36か月（1ページで357,800円） |
| **紬** | **シングル 1ページ 39,800円 買い切り** | 運用月額（任意）＋ページの積み増し（差額のみ） |

**シングルは月額制の約4か月分。** そこで永久に自分のものになる、が一行で言える。
上の段に移るときは**差額のみ**（契約書にも書く）。払い直しにはしない。

**あえてサブスクにしなかった理由：** 月額制の9,800円が成立するのは36か月のリースだから。
手で作るこちらが同じ形をとると原価が合わず、しかも
**「払い切るまで渡さない」という相手と同じ構造**になって、主張そのものが崩れる。

### 高い行を消していない
| ページ数 | 月額制 36か月 | 紬 36か月 | 差 |
|---|---|---|---|
| 1ページ | 357,800円 | **248,600円** | **−109,200円** |
| 6ページ | 537,800円 | 550,800円 | ＋13,000円（ほぼ同額） |
| 12ページ / 9ページ | 717,800円 | 974,000円 | ＋256,200円 |

**12ページ級で負けている行も、そのまま出している。**
差の中身（出張撮影・取材原稿・修正の回数制限なし・マップ運用）を隣に書き、
**「素材が手元にあって更新もしない方には月額制のほうが向いています」**と明記した。
都合の悪い行を消すと、勝っている行も信用されない。

### 検証に入れたこと
- **29 価格の一致** … `src/data/prices.ts` の計算結果が実際にページに出ているか。
  運用プランを1つ足したとき、**添字で引いていた箇所が静かにずれて全ページの月額が下振れした。**
  同じ事故を防ぐため、`run(key)` で引くことにして、結果を検査する
- **30 他社比較の出典** … 金額を並べる以上、いつ時点の公開情報かを必ず添える。
  **他社名はサイトに書かない。**比べるのは仕組みであって、名指しで叩く商売はしない

## 説明文の行き先（約束を書いておく場所）

「変更は何回でも無料」「やめてもサイトは残ります」と本文で言う以上、
**その条件が書いてある場所が要ります。**ないまま言うと、ただのうたい文句になります。

| ページ | 何のために要るか |
|---|---|
| `owned.html` | 主張の本体。借地との対応表、法律の正確な話、所有の4要素、5つの確認質問、移行手順 |
| `terms.html` | サイト上の約束の根拠。所有権の扱い・解約したときの扱い・変更の範囲・できないこと |
| `flow.html` | 「約6週間でお渡し」の中身。10手順と、補助金を使う場合の順序の違い |
| `faq.html` | 電話の前に確かめたいこと。**FAQの構造化データは付けない**（2026年5月に検索表示が終了） |
| `privacy.html` | 問い合わせフォームが個人情報を取るので必要。**アクセス解析もCookieも入れていない**ことを明記 |
| `legal.html` | 特定商取引法に基づく表記。価格を出して役務を売る以上、置いておく |

`verify` の **25「必須ページ」**が、この4枚（owned / terms / privacy / legal）の存在と、
**全ページから1タップで到達できること**を検査します。フッターの下段に別枠で置いてあります。

## 技術的な判断とその理由

| 判断 | 理由 |
|---|---|
| **デザイントークンを JSON の正本から生成する** | 色や寸法を CSS に直接書くと、同じ値が何か所にも散る。`design.tokens.json` を正本にして `npm run build` と `verify` の両方が同期を検査するので、生成物とのずれが納品前に必ず止まる |
| **`@layer base, components, screens, overrides`** | セレクターの強さの競争を避ける。上書きしたいときは層を選べばよく、`!important` を積む必要がない |
| **Container Queries（960/520px）** | カードの列数を「画面の幅」ではなく「置かれた場所の幅」で決める。サイドバーの中や顧客サイトの別レイアウトへそのまま持っていける |
| **日本語は端末の書体（Hiragino Sans / Meiryo）** | ガイドの CSS 指定どおり。**Webフォントを読まないので外部依存とレンダリングブロックが消え、LCP が実測 0.30 秒**になった |
| **Next.js（Pages Router）で書いて、静的HTMLに書き出す** | 部品と型は React・TypeScript で持ち、納品物は素のHTML。App Router は静的書き出しでも全ページに約173KB（gzip）のJSを配るので使わない（`README.md`「なぜ Pages Router なのか」）。実行時JSが0バイトになり、LCPが最速になる。どのホスティングにも置ける |
| **実行時JavaScript 0バイト** | `/spec` で「0バイト」と書いている以上、`verify` が機械的に検証している。インラインのイベントハンドラも禁止 |
| **ヒーローに画像を使わない** | 文字がLCP要素になるのが最速。かつ**素材写真を使わずに済む**。顧客サイトでは実写を使い、そのとき `fetchpriority="high"` と `loading="lazy"` の規則を `verify` が検査する |
| **タップ領域は44px（WCAGの最小は24px）** | 読み手が50〜60代の店主・社長なので、最低基準ではなく実用基準を採った |
| **`llms.txt` を出力しない** | 根拠がないため。`verify` が「生成されていないこと」を検証している |
| **`FAQPage` 構造化データを使わない** | 2026年5月7日に表示終了。`verify` が混入を検出する |
| **ページ名をフラットな `.html`** | どのホスティングでも確実に動く。クリーンURLはホスト側の設定でやる |

## 検証している項目

`verify` が見ているもの。**1件でもFAILがあれば `exit 1` になります。**

### 静的検証（ブラウザ不要）
- 全ページに `tel:` リンクがあり、番号が**文字**で入っている（画像の電話番号は不可）
- 営業時間・住所が文字で入っている
- `lang="ja"` / viewport / `h1` がちょうど1つ
- JSON-LD が valid で、`@type` `name` `address` `telephone` が揃っている
- `FAQPage` が混入していない
- 全 `<img>` に `alt` がある。**先頭画像に `loading="lazy"` が付いていない**
- 実行時JSが無い（`<script>` もインラインイベントハンドラも0件）
- 内部リンクがすべて解決する
- CSSカスタムプロパティが全部定義されている（未定義参照の検出）
- フォームの `<label for>` と入力の `id` が一対一で対応している
- 料金ページに全プランの金額が載っている
- 業種別ページが4本ある
- **`design.tokens.json` と `tokens.css` が同期している**（ずれていたら納品しない）
- **ガイドの実測値15項目がそのまま出ている**（62/54px、315×57、260×48、1104px、720px、45/24px、`#0B0B0D`、`#42D083`、`#626873`、角丸…）
- **使わないと決めた値が混入していない**（`#858A95`、明朝、外部フォントの読み込み）
- **全ページに og:image があり、その画像が out に実在する**（真っ白な共有カードを出さない）
- **ファビコンと apple-touch-icon が入っている**
- `src/data/config.ts` に仮の値が残ったまま公開されようとしていないか
- title / description の長さ、ページ容量

### ブラウザ実測（Playwright + Chromium）
- **LCP 2.5秒以内**（全ページ・`PerformanceObserver` の実測値）
- **横スクロールが発生しない**（幅390px＝ガイドの検証寸法）── 自前で `overflow-x` を持つ器は除外
- **タップ領域 44px以上**（幅390px・本文中のインラインリンクは除外。WCAG AA の最小は24pxで、44pxは本ガイドの推奨値）
- **コントラスト比 WCAG AA**（34箇所。フォント実サイズと太さから大文字判定を分ける）
- **図の色が良／悪で区別できるか**（同色になると帯や印の意味が消える）
- **図のコントラスト比 WCAG AA**（全ページ。SVGの `<text>` は `color` ではなく `fill` と
  `opacity` で色が決まるので、本文用の検査では捕まらない。合成してから最悪値を出す）
- コンソールエラーが無い
- スクリーンショット出力（`shot-desktop.png` / `shot-mobile.png` / `shot-price.png`）

### 検証で実際に見つかった不具合

この仕組みを作った初回で、**目視では気づきにくい3件**が出ました。

1. **ヘッダーの電話番号が赤地に赤で描画されていた。**
   `.tel .num` が、表のバツ印用に定義した `.no{color: 朱}` を拾っていたCSSのカスケード衝突。
   → コントラスト検査に `.tel .num` を追加して、機械で捕まえられるようにしました。
2. **13ページで `<h1>` が0個だった。**
   セクション見出しが全部 `<h2>` だったため。
   → ページの先頭の見出しを `h1` にすることを不変条件にして（`<Section h1>`）、`verify` が検査します。
3. **1ページだけタップ領域の判定が誤検出していた。**
   CSS適用前に計測していた競合状態。
   → スタイルシートの適用完了を待ってから計測するようにしました。
4. **図の朱色の注記が、墨紺の節の上で 2.94:1 しか出ていなかった。**
   SVGの `<text>` は `fill` で色が決まるため、本文用のコントラスト検査を素通りしていました。
   → 図専用の検査を足し、`section.dark .fig` でトークンを明るい側に振り替えました。

### ガイドに従って**変えた**ところ

- **緑のボタンは暗い文字にしました。** 実測の緑＋白文字は約 1.98:1 で、通常文字に必要な 4.5:1 を
  下回ります（05 に明記）。`--nah-theme-campaign-accent-ink` を `#0B0B0D` にしています。
- **明朝と朱色をやめました。** ガイドの書体スタックは端末の日本語ゴシックで、大きな面は無彩色、
  装飾色は行動のためだけに残す（原則E）ためです。結果として**Webフォントの読み込みが 0 になり、
  LCP が 0.21 秒 → 0.30 秒（外部遮断なしの実測）になり、「フォントの自ホスティング」の宿題も消えました。**
- **業務状態の色をブランド色から分けました。** 図の「解約するとサイトは消えます」は緑ではなく
  注意の色（`--nah-color-alert`）です。赤・黄・緑の状態はブランド色と意味を分離する（原則E）。

### テーマの振り替え

ガイド 16 のとおり、ブランド色は**キャンペーン（緑）かプロダクト（青）のどちらか**に決めます。
`src/data/config.ts` の `PROFILE` を変えるだけで全ページが切り替わります。

```ts
export const PROFILE = 'campaign' as const;   // 緑。コンバージョンLP向け（このサイトの既定）
export const PROFILE = 'main' as const;       // 青。プロダクト面向け
```

### 部品と C 番号

ガイド 08〜10 の C01–C24 に対応させています。**操作・ARIA・例外状態は移植先で満たす契約**であって、
原サイトの実装を写したものではありません。

### ガイドに**書かれていないこと**は、原サイトの仕様として扱いません

入力・エラー・読み込み・権限・空状態・キーボード操作は、ガイド自身が「別途設計する」と
書いている領域です（01・13）。このサイトでは `verify` が満たすべき条件を定義しています。

### アイコンは「道しるべ」にだけ使う

アイコンは**語を置き換えたときだけ**読む量を減らします。見出しの横に添えても文字列は結局読まれるので、
解読するものが1つ増えるだけです。そこでこの2種類に限定しています。

**① すでに学習済みの記号（語を置き換える）**
電話・✓／✗・警告。これ以外の「意味を持つ記号」は作りません。

**② 章の目印（6＋4個の閉じた組）**
`price` `unlimited` `cost-cut` `subsidy` `spec` `works` の6ページに固有の字を1つずつ割り当て、
**ナビ・章ラベル・カード見出しで必ず同じ字を使います**（`<Section navKey="price.html">`）。
業種4つも同様に、`.inds` の中だけで使う閉じた組です。

繰り返すから記号として学習され、ページを開いた瞬間に行き先が分かる。
1項目ごとに散らすのとは別物で、散らすと「AI感」に戻ります。**それ以外の場所には付けません。**

Lucide 公式SVG（lucide-static v0.454.0, ISC）を**ビルド時に埋め込み**。`src/data/icons.ts` に57種。
実行時の読み込みはゼロです。

```bash
curl -s https://cdn.jsdelivr.net/npm/lucide-static@0.454.0/icons/<name>.svg
# 中身のパスを src/data/icons.ts の ICONS に追加して <Icon name="<name>" /> で呼ぶ
```

`verify` が**すべてのインラインSVGに `aria-hidden="true"` か `role="img"` が付いているか**を
検査します（装飾アイコンは読み上げない、図は読み上げる、のどちらかに必ず倒すため）。

## スマホ表示

**ここを主戦場として設計している。** 営業の主経路が「電話 → URLを送る」で、
送った先はほぼスマートフォンだから。PCの見た目を縮めたものにはしない。

### 測ってから直す
毎回この順で回している。推測で触らない。

```
390px で（1）横スクロールする領域（2）14px未満の文字（3）アイコンと文字の比 を数える
→ 直す → 数え直す
```

| 指標 | 前 | 後 |
|---|---|---|
| 横に引かないと見えない領域 | 21 | **5**（4列の比較表だけ） |
| 12px未満の文字 | 300箇所超 | **0** |
| アイコンと文字の比 | 0.88〜1.20 倍とばらつき | **1.15 / 1.25 の2種類だけ** |
| 図の中の最小文字（実寸） | 8px（722の図を480pxに縮小） | **12.1px** |

（2）と（3）は `verify` の **27 文字の下限** と **28 アイコンと文字の比** に入れた。
数値を戻したら納品前に落ちる。

### アイコンは px ではなく em で決める
同じ `.ic-sm` が 12.5px の章ラベルにも 17px の見出しにも入るので、
px で固定すると場所ごとに比が変わり、行の中で浮いて見えていた。
`1.15em` / `1.25em` にすると比は常に一定になる。

線の太さも見た目で合わせている。小さく描くほど線は細く見えるので、
**描画後の線幅が約1.5pxに揃うよう** `stroke-width` を逆に振る（小さい方を太く）。

### 文字の下限を上げる（色は濃くしない）
補助文字 `#626873` は白地で 5.8:1 あり、読みにくさの原因は明度差ではなく**字面の小ささ**だった。
ガイド06の寸法はPC向けなので、768px以下では `--nah-font-size-meta` ほか十数か所を引き上げている。
根拠はタップ領域44pxと同じ（読み手が50〜60代であるという前提）。

白（#FFFFFF）と補助面（#F4F5F7）の差は屋外の画面では見分けがつかないので、
**色を濃くする代わりに章の境目へ1pxの線**を入れて区切りを出している。

### 横に引かせない
| もの | 前 | 後 |
|---|---|---|
| 2〜3列の表 | 横スクロール＋見出し固定 | **1行ずつ縦に開く。**列名は `data-h` から各値の頭に出す |
| 4列以上の表 | 同上 | そのまま（縦に開くと1行が長くなりすぎる） |
| 表の脚注 | 器の中にいて画面外で切れていた | 器の外に出して折り返す |
| 全部の図 | 722〜776 の viewBox を 480px に縮小＝文字が8px | **縦に組み直した専用SVGに差し替え（`.fw`/`.fn`）** |
| 制作の流れ（4列10行） | 横スクロール | **縦の手順表（`.flow`）に作り替え** |

時間軸の図（`after_two_years` / `subsidy_timeline`）も例外にしなかった。
「横であることに意味がある」より「**読めない軸よりは読める並び**」を採った。

### 指の下でのふるまい
JavaScript は0バイトのまま、CSSだけで。

| やったこと | なぜ |
|---|---|
| `touch-action: manipulation` | ダブルタップ判定の待ち時間（約300ms）を消す |
| `:active` で 0.97 倍・120ms | **アプリらしさの大半はここ。**色ではなく反応の速さで決まる |
| `-webkit-tap-highlight-color: transparent` | 端末まかせの灰色い矩形を、上の `:active` に置き換える |
| `scroll-behavior: smooth` ＋ `scroll-padding-top` | ページ内リンクが固定ヘッダーの下に潜らない |
| `overscroll-behavior: contain` | 表を引き切った勢いがページに渡って「戻る」に化けるのを止める |
| `@view-transition { navigation: auto }` | ページ遷移が一拍つながる。ヘッダーと下部CTAは `view-transition-name` で動かさない |
| スクロール駆動アニメーションの進捗バー | 読み進みの目安。`@supports` で囲ってあるので非対応なら出ないだけ |

動きを減らす設定の人には、上の全部を切っている（`prefers-reduced-motion`）。

**やらなかったこと：`content-visibility: auto`。**
LCPが実測0.30秒で描画が詰まっていないのに、
スクロール中の高さ推定のずれ（バーが跳ねる）というリスクだけ増えるため。

360 / 390 / 430px に加え 320 / 768px でも横あふれ0を確認している。

- **`marker` の id は図ごとに固有にする。**1ページに複数の図が載るため、

## 公開前にやること

1. `src/data/config.ts` の `PLACEHOLDER = false` にする（ページ上部の「準備中」の帯が消えます）
2. `AREA` / `DOMAIN` / `TEL` / `EMAIL` / 住所 / 2人のプロフィールを実際の値に
3. `FORM_ENDPOINT` に問い合わせフォームの送信先を設定する
   （**設定と同時に、通知をメールとLINE（またはSMS）の2系統に分けること**。
   「問い合わせに気づかない」が最大の失注要因です）
4. `LINE_URL` を設定する（未設定ならLINE導線は自動的に出ません）
5. `npm run build && npm run verify` を実行して **FAIL 0 を確認する**
6. `out/` をそのまま公開（Cloudflare Pages / Netlify / Vercel / S3 いずれでも動きます）

`PLACEHOLDER = false` にすると、`verify` は `example.jp` や `0000` といった
**仮の値が残っていないかを検査してFAILにします。**

## 移行の記録（2026年9月・Python／Astro → Next.js）

Python のジェネレータ（`svc/`）→ Astro（`svc-astro/`）→ **Next.js（`site/`）** の順に移した。
旧版はコミット `01f39d4`（`main`）に残っている（`git show 01f39d4:svc/verify.py` のように読める）。

移植が正しいかは、見た目ではなく**同じ入力に対する出力の一致**で確かめた。

| 何を | どう比べたか | 結果 |
|---|---|---|
| 21ページの HTML | Astro 版の出力と、タグ・属性・本文の並びで突き合わせ（空白・属性の順序・図の marker id の番号は見ない） | **21/21 一致**（意図して直した `contact.html` の文言1か所を除く） |
| robots.txt / sitemap.xml / theme.css | バイト比較 | 一致（theme.css は生成元パスのコメント2行だけが違う） |
| 検査 | Python 版 `verify.py` と TS 版 `verify` を、同じ出力に対して項目ごとに突き合わせ | **582件すべて一致**（並び順も同じ） |
| Next.js 版の出力 | Python 版・TS 版の両方の検査にかける | どちらも **PASS 581 / WARN 1 / FAIL 0** |
| OGP画像 | 同じマシンで Python 版と TS 版（`scripts/og.ts`）を実行して比較 | 24ファイルすべてピクセル一致 |
| デザイントークン | 旧 `build-tokens.mjs` と TS 版の出力 | バイト一致（見出しコメントのパスだけ更新） |
| 出力の再現性 | 同じ入力で2回ビルドして HTML のハッシュを比較 | 一致 |

移行の途中で見つけて直したこと：

- **図の marker id が通し番号だった。** ページを並列に書き出す Next.js ではビルドのたびに番号が変わる。aria-label から決まる値に変えた
- **Next.js が head に付ける `data-next-head=""` で、検査の `<title>` と JSON-LD の照合が外れた**（FAIL 21件）。JS を配らない以上は役目のない印なので、`postbuild` で消している
- **React は `ほか{n}項目` を `ほか<!-- -->5<!-- -->項目` と出す。** テンプレートリテラルで1つにする決まりにして、`postbuild` で検出する
- **OGP画像の金額と返信の約束が、カードにだけ手書きで残っていた。** `prices.ts` / `config.ts` から引くようにした（いまの値では出力は同じ）
- **OGP画像の生成が、出力先のディレクトリを丸ごと消していた。** 上書きに変えた

残っている注意：

- **コミット済みの OGP画像（`public/og/`）は別のマシンで作ったもの。** この Mac で `npm run og` を実行すると、日本語の書体の違い（Noto Sans CJK JP と Hiragino Sans と見ている）で全PNGが差分になる。どちらの字形を正本にするか決めてから作り直すこと
- **ページに出す検査の件数（`works.html` の「581項目」）は、ビルド時点の `verify-report.json` から取る。** 数字を最新にするには `npm run build && npm run verify && npm run build` の順に回す
