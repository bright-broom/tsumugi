# 確認の手順書：オーナー・専門家・実機で確かめること

[#103](https://github.com/bright-broom/tsumugi/issues/103) の **A（専門家・オーナーの確認）** と **B（実機・実到達の確認）** を、短い時間で終えるための手順。コードと自動検査では代われない部分だけを扱う。

- **確認した人の記録が要る。** 受入記録（`checkedBy` は `owner`・`staff`・`customer`）も専門家の承認記録も、確認していない人が書けば記録の捏造になる。AI や作業者は、この文書で準備をし、確認の結果を受け取って反映するところまでを行う。
- 各表の「自動で確かめた事実」は 2026-09-26 の main（`99c728c`）のビルドを見たもの。確認の出発点で、確認そのものではない。
- 確認を終えたら、結果（日付・確認した人の立場・根拠の場所・確認済みか対象外か）を伝えれば、記録の反映と検査はこちらで行う。自分で記録する場合の書き方は [本番検査の WARN 3 件](publication-warnings.md) の「記録のしかた」。

## A1. 受入確認 18 項目（紬の自社サイト）

項目の定義と「対象外にできる条件」は [publication-warnings.md の表](publication-warnings.md#3受入確認-18-項目) が正本。ここでは紬の自社サイトで**どこを開いて何を見るか**を書く。確認・対象外の判断はオーナーが実物を見て行う（この文書では決めない）。

| 項目               | 開くページ                                | 見ること                                                                     | 自動で確かめた事実                                                                                                                                      |
| ------------------ | ----------------------------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `phone`            | 全ページ（スマホ・PC）                    | ページの上部で番号が読め、押すと発信の画面になるか                           | 全 22 ページのヘッダーに `tel:08045601124` と番号の文字（検査「01」）                                                                                   |
| `hours`            | `/contact.html`・フッター                 | 受付時間と、定休日・年末年始の扱いが書かれているか。古い案内が残っていないか | 「8:00〜22:00（土日も対応）」「メール 24 時間受付」。**定休日・年末年始の記載は見当たらない**（年中対応なら、その旨で足りるかを判断）                   |
| `address`          | `/contact.html`・`/legal.html`            | 地図・道順・駐車場が要るか                                                   | 所在地は掲載。打ち合わせは「オンラインと電話」。**来店を受け付けないなら「対象外」の条件に当たる**                                                      |
| `price`            | `/price.html`・`/plans.html`              | 追加費用がかかる条件が料金と並んで書かれているか                             | 外部実費・変更枠の超過・増築の充当条件を料金の近くに掲載。価格は `prices.ts` と一致（検査「29」）                                                       |
| `primary-contact`  | `/restaurant.html` ほか業種 4 ページ      | 紬が実際に対応できる窓口（電話・メール）が主役になっているか                 | 自社はメールと電話の受付（ADR 0051）。フォームは出していない                                                                                            |
| `area`             | `/about.html`・`/contact.html`            | 受けられる地域と、費用が変わる条件                                           | 「全国どこでもお受けします」「打ち合わせはオンラインと電話」。出張の有無・費用の記載は見当たらない                                                      |
| `photos`           | 全ページ                                  | 実物の写真を載せているか                                                     | 画像はトップのヒーローの絵（イラスト）だけ。**実物の写真は無い**（「写真を載せないページ・プラン」に当たるかを判断）                                    |
| `staff`            | `/about.html`                             | 掲載の同意・顔写真・担当・経歴・得意分野                                     | 2 名の紹介文あり。**顔写真は無い**（同意を得ていないなら対象外の条件に当たる）                                                                          |
| `cases`            | `/works.html`                             | 一覧と詳細の 2 段と掲載許可                                                  | 事例は自社サイト 1 件だけ。顧客事例は「これから」                                                                                                       |
| `voices`           | 全ページ                                  | お客様の声と依頼・謝礼の表記                                                 | お客様の声は載せていない                                                                                                                                |
| `guides`           | `/price.html`・`/faq.html`・`/owned.html` | 料金・費用・選び方の説明が、提供しているプランの範囲か                       | —                                                                                                                                                       |
| `mobile-parity`    | 料金・注意事項・連絡先のあるページ        | スマホと PC で同じ情報が確認できるか                                         | 21 ページ × 9 幅で横はみ出し 0・最小の文字 14px（2026-09-26 の計測）                                                                                    |
| `no-score-chasing` | トップ・料金・相談                        | **実機で**電話・メール・メニューを操作したか                                 | → 下の「B. 実機の確認」がそのまま根拠になる                                                                                                             |
| `tap-target`       | スマホの全ページ                          | 隣のボタンを押し間違えにくい間隔か                                           | 1 つずつの大きさは 44px 以上（検査「16」）                                                                                                              |

| `business-profile` | Google ビジネスプロフィール               | プロフィールからサイトへ移動でき、住所・時間が一致するか                     | プロフィールの有無はリポジトリからは分からない。**持たないなら対象外の条件に当たる**                                                                    |

| `reviews`          | GBP の口コミ                              | 依頼・返信の運用を始めたか                                                   | 口コミの運用を含む支援を自社に適用していないなら対象外の条件に当たる                                                                                    |

### 根拠の残し方

`evidence` には確認メモの置き場所を書く。リポジトリに置く場合の例（個人情報は書かない）：

```md
# 受入確認 2026-10-01（phone）

- 確認した人：owner
- 端末：iPhone（iOS 18・Safari）、MacBook（Safari）
- 見たページ：/index.html、/price.html、/contact.html
- 結果：上部に番号が読める。押すと発信の画面に 080-4560-1124 が出る（発信はしていない）
- 判断：confirmed
```

## A2. 規約・特定商取引法の表記：弁護士に渡すもの

手順・記録の書き方・確認してほしい点は [publication-warnings.md の 1・2](publication-warnings.md#12規約と特定商取引法の表記の専門家確認) が正本。依頼の時に次をそろえて渡す。

- [ ] 公開中のページ：`https://tsumugi-six.vercel.app/terms.html`・`/legal.html`（印刷して PDF にしてもよい）
- [ ] 確認を受ける版の SHA-256（`npm run verify -- --mode production` の WARN の詳細に出る値。2026-09-26 時点は terms `fc7e1ace…`・legal `0cdf0b0d…`）
- [ ] 料金と支払の実際：`/price.html`（着手 50%・検収 50%、銀行振込、自社 24 回分割の新規受付なし、増築の充当条件、支援の月額と終了の申し出）
- [ ] 質問：フリーランス法第 4 条（取引条件の明示）への対応として、この規約と見積書・請求書で足りるか。中止時の精算・無償修補の範囲・変更枠の記載に不足はないか
- [ ] 特定商取引法の表記は、通信販売に当たる場合の記載事項として足りるか（事業者向けの役務が中心であることを伝える）

## A3. 税理士に確認すること（消費税の表示と請求）

請求書の仕組み（`npm run ops:invoice`、[ADR 0078](../architecture/0078-invoices-and-payments.md)）は、次の前提で作ってある。**前提が正しいかを税理士に確認する。**

| 現在の扱い                                                                                                                                         | 根拠の場所                                |
| -------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| 公開している料金はすべて**税別**。サイトの特定商取引法の表記にも「金額はすべて税別で表示」                                                         | `/legal.html`・`/price.html`              |
| 請求書は税別額に **10% を上乗せ**して請求する                                                                                                      | `tools/ops/billing/`                      |
| インボイス（適格請求書発行事業者）は**未登録**。請求書に「当方は適格請求書発行事業者の登録をしていません。本書は適格請求書ではありません。」と書く | 請求書の見本（status.md「請求書の見本」） |
| 支払は着手時 50%・検収時 50%。継続支援は月ごとに請求                                                                                               | `/price.html`                             |

確認したいこと：

1. 免税事業者として、10% の上乗せを「消費税」と書いて請求してよいか。書き方（例：「消費税相当額」）を変えるべきか。
2. お客様は事業者が中心。料金を税別だけで表示していることは、表示のルール上問題ないか（個人のお客様がいる場合を含めて）。
3. お客様（課税事業者）側の仕入税額控除への影響。未登録の事業者からの仕入れの控除の経過措置は、2026 年 10 月以降に割合が下がると理解しているが正しいか。それを踏まえて、登録するかどうか・いつ判断すべきか。
4. 免税でいられる条件（基準期間の課税売上高など）を、どの数字で見張ればよいか。
5. 着手時の 50%（前受け）の売上の計上時期。

確認の結果、表示や計算を変える場合は、料金の表示（`src/content/prices.ts` と i18n）・請求書（`tools/ops/billing/`）・特定商取引法の表記を同時に直す（表記を変えると A2 の確認をし直す）。

| 確認先                                  | 手順                                                                                                                                        | 記録すること                                               |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 商標（J-PlatPat）                       | 「商標」→「称呼（単純文字列検索）」で「ツムギ」、区分 **35 類・42 類** で検索。似た読み（「ツムギヤ」など）と、図形・文字の組み合わせも見る | 検索日・件数・近い登録の有無。判断に迷うものは弁理士に相談 |

## B. 実機の確認

Chromium での自動計測（21 ページ × 9 幅・メニューの 28 項目）は済んでいる。ここでは**実機の Safari と読み上げ**、**実際の到達**を確かめる。

### B1. iPhone の Safari（iOS 17 以上）

- [ ] トップ：ヒーローの見出しと補助文が絵の中に収まり、欠けていない（縦・横の両方）
- [ ] メニュー：「メニュー」を押すとヘッダーの下に開く → 外側（本文）を押すと閉じる → もう一度開き、外側のリンク（例：「ご相談」ボタン）を**1 回**押すとそのページへ移る
- [ ] メニュー：パネルの中のリンクで移動できる。「閉じる」を押すと閉じる
- [ ] 電話：ヘッダーと下部の電話を押すと、発信の画面に `080-4560-1124` が出る（発信しなくてよい）
- [ ] メール：メールのリンクを押すと、宛先が入った新規メールが開く
- [ ] 料金ページ：表を指で横に動かせ、ページ全体は横に揺れない
- [ ] 文字の拡大：Safari の「ぁあ」→ 200% で、トップ・料金・相談の文字が欠けず、横スクロールが出ない

### B2. VoiceOver（iPhone：設定 → アクセシビリティ → VoiceOver）

- [ ] メニューのボタンが「メニュー、ボタン」と読まれ、開くと開いた状態が伝わる
- [ ] ヒーローの絵の説明が 1 回だけ読まれ、続けて見出しが読まれる（同じ文が 2 回読まれない）
- [ ] 電話・メールのリンクで、番号・宛先が読まれる

### B3. Mac の Safari（17 以上）

- [ ] メニューが開き、Esc で閉じ、フォーカスがボタンへ戻る（Tab で移動して確かめる）

**Safari 16 以前**では、メニューのボタンは出ない（ブラウザが popover に対応しないため。全ページの案内はフッターにある。[ADR 0086](../architecture/0086-popover-menu-and-font-choice.md)）。そうした端末を使うお客様が多いと分かったら、判断をし直す。

### B4. 実際の到達（電話・メール）

- [ ] 外部のメールアドレスから問い合わせ先へテストのメールを送り、届いたことと返信までの時間を記録する
- [ ] 受付時間内に、別の人の電話から問い合わせ番号へかけ、つながることと担当の引継ぎを確かめる

### B5. 料金ページのドメインの取得先（公式ページとの照合）

料金ページの記載（公式情報の確認日：2026 年 9 月 17 日）と、各社の公式ページを見比べる。違っていたら `src/i18n/locales/ja/` の該当する文言と確認日を直す。

| 取得先               | リンク                              | サイトに書いていること                                                  |
| -------------------- | ----------------------------------- | ----------------------------------------------------------------------- |
| さくらのドメイン     | https://domain.sakura.ad.jp/        | .jp や .com などに対応し、電話・メールで相談できる                      |
| ムームードメイン     | https://muumuu-domain.com/          | .com・.jp など幅広い種類。日本語のマニュアルやサポート                  |
| Cloudflare Registrar | https://www.cloudflare.com/domains/ | 取得・更新料金に独自の上乗せをしない。利用中は Cloudflare の DNS が必要 |

### 記録

B1〜B3 の結果は A1 の `no-score-chasing`・`mobile-parity`・`phone` の根拠に、B4 は `notifications` と `hours` の根拠に使える。確認メモ（端末・OS・日付・結果）を残し、その場所を伝える。
