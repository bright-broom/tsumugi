# 料金と試算資料を引き継ぐ

料金の採用判断は [2026-09-18新料金表](pricing-2026-09-18.md)、実装判断は [ADR0075](../architecture/0075-pricing-reset.md)。ブランチ・PR・公開状態・検証対象は [status](../status.md) を確認する。個人のメモリや `.artifacts/` 内の一時スクリプトを前提にしない。

## 現行と履歴を混同しない

| 用途 | 正本・参照先 |
|---|---|
| 販売価格・参考額・受付状態・総額計算 | `src/content/prices.ts` |
| 顧客へ約束する範囲 | `src/i18n/locales/ja/prices.ts`、`price.ts`、`catalog.ts`、`terms.ts` |
| 採用理由と事業の規範 | [新料金表](pricing-2026-09-18.md)、[ビジネスガイドライン](紬_ビジネスガイドライン.md) |
| 現行の基本商品と経営仮定 | `tools/pricing/proposal.json`、`model.ts`、`report.ts` |
| 現行の価格を写したExcel | `紬_事業の中身.xlsx`、`紬_全プラン比較・料金試算.xlsx` |
| 過去の検討履歴 | `pricing-redesign-140h.md`、`premium-pricing-proposal.md`、`premium-pricing-assumptions.json`、`premium-pricing-scenarios.csv`、`cost-review-2026-09-18.md`、`紬_費用総点検_2026-09-18.xlsx` |

履歴の79,800円・99,800円等を現在の価格へ戻さない。旧上位案JSON/CSVは現行料金へ同期する入力ではない。未発売の上位商品の現在の参考額は `PROPOSED_PRICES` と新料金表を使う。Excelの編集はサイトへ反映されない。

## 変更時の順番

1. `prices.ts` のキーを保って変更する。通常商品と `PROPOSED_PRICES` を混ぜない。`preparing` は価格の確定・丸めとは別に判断する。
2. `proposal.json` の価格・工数・提供可能な受注構成、説明文と規約、ガイドを同期する。実測していない固定費・獲得費・決済率は仮定と明示し、値下げして採算を作らない。
3. `npm run --silent report:pricing` で単品採算・全本人時間控除後の余力・複合ストレスを確認する。赤字・枠超過も残す。外部費月3,500円は比較仮定で、紬への一律請求ではない。
4. 顧客総額、税、支払分割、追加ページ、補助金例、比較表、OGPを確認する。`npm run og -- --out <一時ディレクトリ>` で生成・目視確認し、必要な `public/og/` を更新する。ファビコン等の無関係な差分を混ぜない。
5. 下記Excelを同期・再計算する。過去の監査Excelは当時の未採用案として保持する。
6. `npm run validate` と `npm run verify -- --mode production` を実行。料金関連ページを狭幅/広幅で確認する。保存済みの見積もりを移行・上書きしない。`tests/ops/estimate.test.ts` は旧版の金額保持と新版への新価格適用を検査する。
7. 規約文面が変わると自社公開判断のハッシュも失効する。`src/content/publication.ts` とADR0056/0075の対象範囲を確認する。ハッシュの更新を専門家承認として扱わず、`LEGAL_APPROVALS` / `ACCEPTANCE_RECORDS` を架空の値で埋めない。

公開用出力は [引き継ぎ手順](../handoff.md) のクリーンなコミットで build → 本番モードverify → build の順に作る。

## Excelの入力場所と再計算

既存の書式と数式を保ち、入力セル・説明文を更新する。Pythonを使う場合は `openpyxl`、再計算はExcelまたはLibreOfficeが別途必要。これらはNodeのアプリ依存ではない。既存ファイルをコピーして作業し、確認後に差し替える。

| ファイル・シート | 主な入力場所 |
|---|---|
| 事業の中身／料金レバー | 制作 `C7:C9`、月額 `C20:C23`、工数 `C49:C53`。`C54:C56` は将来ケースの社数で、現行モデル22社の構成とは別 |
| 事業の中身／オプション・標準装備 | `A6:C13` の名称・金額・範囲。補助金シート `C9` の撮影参考額も価格正本と照合 |
| 全プラン比較／01 制作プラン | `C6:C11`。下3件は未採用の参考額 |
| 全プラン比較／02 月額サポート | `C6:C10`。技術保守は未発売。範囲はG/H列も照合 |
| 全プラン比較／03 追加オプション | `A6:C13`、`E6:E13`。定額/個別見積/受付準備中の区分を保持 |
| 全プラン比較／07 計算前提 | 工数 `H28:H30`、`H39:H41`。現金費・固定費等は仮定のまま。旧案行を販売商品にしない |
| 全プラン比較／06 受注構成 | 現行モデルは15行目。土台 `C15`、CMS `D15`、支援 `J15:L15`。他の行は別ケース |

2026-09-18にはマクロ経由のLibreOffice再計算がタイムアウトした。同じ形式へのheadless変換なら再計算できた。コピーした入力を別ディレクトリへ出力する例：

```bash
soffice --headless --convert-to xlsx --outdir /tmp/tsumugi-recalculated /tmp/tsumugi-input/*.xlsx
```

終了コードだけでなく、生成先・更新日時・数式のキャッシュを確認する。`openpyxl.load_workbook(..., data_only=False)` と `data_only=True` の2回で読む。全数式の対応セルが欠落せず、Excelエラー型でないことを確認する。**data_onlyで読んだ本を保存しない。** 数式が値に置き換わる。再計算後にopenpyxlで保存するとキャッシュが消えるため、修正後は再計算する。

現行2冊は113＋246＝359数式。式の欠落だけでなく、例えば以下の期待値と照合する（今回の前提を変えたら期待値も独立計算する）。

- 制作100,000/250,000/450,000円、月額0/6,000/12,000/30,000円。
- 全プラン比較「05 月次採算」15行目：売上 `B15=800000`、工数 `D15=61`、全時間評価後 `G15=-13400`、複合ストレス `I15=87.25`。
- 事業の中身「配布用_36か月の総額」`E6=226000`（制作10万円＋外部費仮定3,500円×36か月）。

必要な確認はこの文書とコードから再現する。`.artifacts/pricing-reset/` の更新スクリプトはその時点のセル配置に依存する一時作業用であり、現在のファイルに無条件で再実行しない。
