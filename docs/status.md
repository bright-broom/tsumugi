### デザインの刷新：和モダンの面と余白（2026-09-25）

オーナーの指摘「和風で進めているが全体のまとまりが弱い。訪れた瞬間の『すごい』が無い」に対応した（[ADR0085](architecture/0085-wa-modern-surfaces.md)、方針は [design.md](product/design.md)）。原因はヒーローだけが作り込まれ、**世界観が最初の1画面で終わっていた**こと。方向性は 3 案を示し、オーナーが「和モダン×ダーク」「構成も整える」を選んだ。

- **明暗の帯**：濃い面を奥行きのあるグラデーションと金の細線を持つ帯にし、TOP と下層で明るい面が 3 つ続かない順に並べた。ページの導入（`h1` の章）は既定で帯になり、どのページも同じ開き方になる。
- **見出しは明朝**（屋号と同じ端末の書体、weight 600）。`h3` 以下はゴシックのまま。外部フォントは足していない。
- **数字を主役に**：価格・総額を明朝の特大にし、琥珀は下線と金の文字に絞った。面いっぱいの琥珀だった相談の章は帯へ戻した。
- **箱を減らす**：囲み罫を薄い沈み・金の細線・余白に置き換え、表の外枠を外した。濃い帯に載る図は金の細枠の「図版」にした。
- **織り目**：屋号（紬＝織物）にちなみ、明るい面に 2〜3% の織り目を敷いた（画像を足さず CSS のグラデーション 2 本）。
- 色の原値（アイボリー・エスプレッソ・琥珀）・文言・料金・URL・ページ構成は変えていない。追加した `gold`・`gold-soft`・`ink-deep`・`ink-veil` はすべて 3 色からの混色。

**検証**：`npm run validate` 成功（Vitest 765 件、build 22 ページ・実行時 JS 0、静的検査 FAIL 0）。本番モードの静的検査 **PASS 347 / WARN 3 / FAIL 0**（WARN 3 は従来どおり）。ブラウザ実測（`npm run verify`）はこの作業環境では実行できないため、22 ページ × 1280/375px を DOM 上で走査し、**AA 未満の文字 0 件（14,163 要素）・横あふれ 0 件**を確認した。途中、導入を濃い帯にした時点で 4 ページ・十数箇所が読めなくなっており、この走査で検出して部品ごとに直した。

### 引渡し資料の梱包と再現性の証跡（2026-09-24）

監査 D06「引渡しは参照記録中心。必要資料の梱包・アクセス権・移管後再現性の一括証跡がない」に対応した（[ADR0082](architecture/0082-handover-package.md)、使い方は [tools/ops/README.md](../tools/ops/README.md)）。

- `npm run ops:handover` の 4 段階：`plan`（引き渡せる状態か）→ `pack`（ソース一式＋元素材＋引渡し書＋機械可読な記録を 1 フォルダに）→ `verify`（別フォルダへ取り出し、依存を入れ直してビルドまで通ったときだけ `SHA256SUMS` で封をする）→ `record`（封のある資料だけを CRM の引渡し記録に）。
- CRM に案件のアカウント（種類・サービス・名義・確認日・紬のアクセスと撤回日／保持の理由）を追加し、ドメインとホスティングがお客様名義になるまで「引渡し済み」にしない。パスワード・鍵・トークンらしき文字列は記録の時点で拒否する。
- 引渡し書に載せる検査の実績は、全項目・FAIL 0・引き渡すコミットと同じ・未コミットなしのレポートからだけ取る（[ADR0025](architecture/0025-verified-build-report.md) の判定を再利用）。
- 検証：Vitest **734 件**（新規 8 件）・lint・型／構造／文言／スタイル／未使用の検査が成功。架空の顧客（rehearsal-shop）で相談から引渡し済みまで実 CLI を通し、次の 7 つを断ることを確かめた——名義が未記録／ドメインが紬名義／参照にパスワード／元素材に `.env` と鍵の形／検査レポートが別コミット／封のない資料の記録／封の後の書き換え。梱包したソースは 528 ファイル・5,076,576 バイトが目録と一致。
- 限界：`--build build` の再現確認と本番モードの検査（ブラウザ計測）は、この環境では実行できない。封はオーナーの環境か CI で行う。通し確認の検査レポートは実測ではない見本を使い、資料は作業後に削除した（実データ `.data/` は変更していない）。
