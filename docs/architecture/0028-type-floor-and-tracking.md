# 0028 文字の下限を 14px（10.5pt）に上げ、字間をトークンで開く

- 日付：2026-09-16
- 状態：採用（Issue #57）

## 問題

390px で測ると 12〜13px の文字が 800 箇所以上あり、PC では 11.5px の表の補足もあった。値は各 CSS に `text-[12px]` などの任意値で散らばり、モバイルだけ `--text-meta` を 14px に上書きしていた。図解は SVG の座標の単位で 12〜13.5 を指定しており、表示倍率を掛けた画面上の実寸は 320px 幅で 9.6px まで下がっていた。字間は指定がなく、`palt` で詰めた和文が密に見えていた。

## 判断

- **下限トークン `font.size.fine` = 14px（10.5pt）を追加する。** 11.5〜13.5px の任意値 68 箇所をすべて `text-fine` に置き換え、`font.size.meta` は `{font.size.fine}` を参照する。モバイルだけの `--text-meta: 14px` の上書きは不要になったので消す。
- 14px 以上の文字（本文 16px、見出し、金額、ボタンの 15px など）は変えない。見出しまで一律に拡大しない。
- 12px と 13px の段差はなくなる。補助文字どうしの差は色（`text-muted`）と太さで付ける。段を 14 / 14.5 / 15px に分ける案は、14px の表のセルより表の案内（旧 13px）が大きくなるなど順序が逆転するため採らなかった。
- **字間は `font.tracking.body` = 0.04em、`font.tracking.heading` = 0.02em（旧 0.01em）。** `.nah-app` と見出しに一度だけ当て、ページごとの指定は増やさない。フォーム部品はブラウザ既定の `letter-spacing: normal` を `inherit` にして本文にそろえる。欧文ロゴや大きな金額のように字間を個別に決めている箇所はその値を保つ。和欧文間の半角スペース（ADR 0021）は文字列側の仕組みのまま変えない。
- Tailwind のテーマ名前空間に `font-tracking-* → --tracking-*` を追加し、`tracking-body` / `tracking-heading` をトークンから生成する。
- **図解は画面上の実寸で決める。**
  - 狭い図（幅 `NW` = 340 の座標）は 390px 幅でほぼ等倍に描かれる。補助文字の最小を `NARROW_MIN_TEXT` = 14 とし、`primitives.tsx` と各図の狭い版で 12〜13.5 の指定を置き換えた。文字が大きくなって箱や旗に重なった `OwnershipClock` と `SubsidyTimeline` の狭い版は、座標を下にずらして組み直した。
  - 横長の図（幅 700〜776 の座標）は 1024px 未満では補助文字が 14px を割るため、狭い図への切り替えを 900px から 1023px に上げた。拡大しすぎないよう、狭い図は最大 480px 幅で中央に置く。`SubsidyTimeline` の横長版の 11.5 は 12 にした（1024px で 14.35px）。
- **検査を引き上げる。** `MIN_FONT_MB` を 12 → 14 にする（除外は広げていない）。図解の文字は「SVG の値 × `getScreenCTM` の倍率」で測る `27 図の文字の実寸 14px` を 390px と 1280px に追加した（図のあるページだけ記録）。
- 320px 級の画面では、文字が大きくなった分ヘッダーのメニューが 3px はみ出したので、359px 以下だけヘッダーの間隔を 10px → 6px に詰めた。

## 検証

- 320 / 390 / 768 / 1024 / 1440 / 1920px と、768 / 1024 / 1440 / 1920px の 200% ズーム（CSS 上の幅が半分）で全 21 ページを描画し、HTML の文字はすべての条件で最小 14px、横スクロールなし。
- 図解 6 種を 320 / 390 / 1024px で要素ごとに撮り、文字と箱・旗・破線の重なりがないことを目視で確認した。
- `npm run validate`（型・構造・文言・CSS・未使用・lint・単体テスト・価格モデル・ビルド・静的検査）が通る。
- `npm run verify` のブラウザ実測は、この作業環境ではローカルサーバーの待ち受けが許可されず実行できなかった。追加した `27 図の文字の実寸` の関数は、同じ文字列を上記の描画環境で全ページに実行し、390px と 1280px で違反 0、変更前の出力なら 390px で違反が出ることを確かめた。

## 残る制約

- 狭い図は幅に比例して縮むため、**320px では図解の文字が 11.2px**（変更前 9.6px、+1.2pt）、200% ズームの 768px 窓（CSS 上 384px）では 13.83px になる。検査は読み手の代表寸法 390px で行う。320px でも 14px を保つには狭い図をさらに縦長に組み直す必要があり、今回は見送った。
- 追加する書体（#58）ごとの確認は、書体切り替えの実装後に行う。
