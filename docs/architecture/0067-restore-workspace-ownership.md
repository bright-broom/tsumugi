# 0067 復元テストで既存の作業領域を削除しない

- 日付：2026-09-18
- 状態：採用（main 反映は status.md 参照）

## 背景

監査 A08 の復元経路を確認した際、restoreTest の後片付けが復元先の作成成否にかかわらず `workDir/repo` を削除していた。既存フォルダの検知で clone を拒否した場合も、チェックサム段階で失敗した場合も、既存データを削除できる不具合だった。CLI は通常一時フォルダを生成するが、関数の直接利用や復元領域の競合では保護が必要。

## 判断

clone 直前に復元先を mkdir で排他的に確保する。作成成功後だけこの実行の所有領域として記録し、後片付けは所有領域に限定する。既存フォルダ・通常ファイル・有効なリンク・壊れたリンクはすべて失敗として扱い、変更も削除もしない。存在確認と作成を別に行う方法では、確認後の競合を防げないため採らない。

自分が作成した領域は成功・失敗にかかわらず従来どおり片付け、keep 指定時だけ保持する。目録と bundle は変更しない。作業先とバックアップ先は関数の入口で絶対パスへ解決し、Git の作業ディレクトリ変更による解釈の変化を避ける。

## 検証と限界

既存のフォルダ・ファイル・リンク・壊れたリンクの保持、チェックサム失敗時の既存データ保持、自分の作成領域の成功／clone 失敗と keep の組み合わせを回帰テストする。さらに実リポジトリの bundle を別ディレクトリへ復元し、依存の新規導入とビルドまで検証して所要時間を記録する。実測は [status.md](../status.md) と [運用手順](../operations.md) に残す。

この変更は Git で追跡するリポジトリの復元が対象。独立した保管先、非公開業務データの暗号化・保持・削除、別端末での復旧、継続した週次実行は別の未確認事項で、A08 全体の完了とはしない。チェックサムは破損検出であり、信頼できない配布元の安全性保証ではない。
