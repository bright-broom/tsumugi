# 0069 — Issueをmainの実装で判定し、実配信ヘッダーを監視する

日付：2026-09-18。状態：採用。関連：#32、#41。

## 背景

41件のopen Issueには旧パス・実装前の状態が残る。またPR #82〜84は中間ブランチにマージされ、mainには未反映だった。公開監視はページ本文を検査するが、配信設定が失われた場合を検出しない。

## 決定

- 完了はPRの表示だけでなくmainの実装と照合。中間ブランチの修正を保持してmainへ向けたPRにまとめる。Issueの履歴は残し、完了・集約・実装残・実確認待ちを明記する。
- `siteExpectations()`が既存の`vercel.json`から7つのセキュリティヘッダーを取得。`check:live`と`monitor`はトップ`/`と全取得ページの200応答を照合する。
- ヘッダー名は大文字小文字を区別せず、値は前後空白を除き配備設定と完全一致で検査する。意味的に同等の並べ替えでも差分とするため、意図した変更は配備設定を更新する。個別ホストへ古い設定を押し付けず、対象のコードから実行する。
- 欠落/変更はFAIL、全ページ取得不能/空の期待値もFAIL。応答できない個別ページは既存の応答検査でFAIL。模擬配信は外部の配信設定を証明できないためSKIP。
- 新規リクエストは増やさず、既存GETの応答ヘッダーを使う。公開JS・CSS・依存・価格は変更しない。

## 検証と限界

正常、トップだけの欠落、下層だけの欠落、CSP値の緩和、模擬配信、空設定、全ページ停止、正本の7ヘッダーを回帰検査する。全体検証と実通信結果はstatus.mdを参照。

資産の404/Content-Type・CSS内参照、監視停止の独立検知、通知到達、Search Console、production aliasの配備ID対応は未対応。ヘッダー一致をセキュリティ監査全体の完了としない。
