# ADR 0064: 監視の未実行を成功扱いにせず、公開ページの期待値をコードから照合する

日付: 2026-09-18。状態: 採用。関連: #32、#14、[機能監査](../product/feature-audit-2026-09-18.md)。

## 背景

Site monitor の実行 `35249976398` は success だが Monitor ステップが skipped。リポジトリ変数 SITE_URL が空だった。さらに監視は sitemap に掲載されたページだけを確認し、ページと sitemap の両方から同じ URL が消えれば正常と判定していた。初回検査で見ている canonical・実行時 JS・404 も定期監視では見ていなかった。

制約は、公開ページの実行時 JS 0、メール・電話受付、既存の公開判断と料金を維持すること。監視は読み取りだけで、通話・メール・フォーム送信をしない。

## 選択肢と判断

| 選択肢                                                        | 利点                                                       | 残る問題                                                  |
| ------------------------------------------------------------- | ---------------------------------------------------------- | --------------------------------------------------------- |
| SITE_URL を外部で一度設定するだけ                             | 変更が少ない                                               | 再作成や複製で再発し、未実行が success になるコードが残る |
| 常に DOMAIN へアクセスする                                    | 設定不要                                                   | 未公開の顧客テンプレートや仮設定まで監視しうる            |
| 明示 URL を優先し、自社公開判断に一致する DOMAIN だけ補完する | 現行自社サイトで設定欠落を防ぎ、顧客は明示設定を要求できる | 誤った明示 URL の運用確認は引き続き必要                   |

3 番目を採用する。OWNER_PUBLICATION の全承認条件を監視が再判定するわけではない。公開可否の検査は既存の production verify の責務。

## 実装

- `tools/ops/site-expectations.ts` が固定公開ルートと公開コレクションのパス、問い合わせページと電話・メールのリンクを正本から取得する。404 は公開一覧から除く。顧客がフォームを使う場合、ここでは電話リンクだけを確認し、実フォーム送信の検証を代替しない。
- monitor の対象は `--url`、SITE_URL、自社公開判断に一致する非仮設定 DOMAIN の順。どれも使えない場合は終了コード 2。以前の Actions のスキップ成功を削除する。スケジュール頻度は変更しない。
- check:live と monitor で DNS・証明書・HTTPS 転送・トップ・robots・sitemap・canonical・og:url・JS・404 を共通化する。monitor は取得時間も記録する。同じページは一回の取得結果を使う。
- 期待する URL 一覧と sitemap の不足・未登録・重複を検出。sitemap にない期待ページにも GET する。期待パスが外部を指す設定は通信前に拒否する。
- HTML の robots/googlebot/bingbot meta、HTTP の X-Robots-Tag の noindex/none を確認する。max-image-preview:none と区別する。`template` 内の利用できない連絡先リンクは満足条件に数えない。
- 取得結果を JSON とジョブ要約に記録し、Actions は成功・失敗とも監視 JSON を 14 日保存する。設定エラーや依存導入の失敗では JSON がなくてもジョブを失敗にする。
- 新規依存はない。既存 TypeScript・tsx・parse5・Vitest と固定 SHA の GitHub Actions を利用する。公開ページ・価格・販売可否・生成物の仕様は変更しない。

## 限界と後続

一覧一致は commit・成果物一致の証明ではない。本文改変、CSS・画像の欠落、クリック可能なレイアウト、全検索エンジンの全 robots 指示、実検索掲載、配備 ID と alias の対応は別検証。メールリンクがあることは受信できることの証明ではない。証明書 WARN・遅延 WARN は現行同様に報告のみで、終了コードは FAIL がある場合 1。

GitHub の定期実行には遅延や停止があり、独立した監視・通知先確認・復旧通知を代替しない。外部サービス契約や通知先は今回変更しない。顧客ごとに複製する場合、監視コードのルート・連絡先設定もその顧客のものに揃える。

## 検証

正常系だけでなく、ページと sitemap の同時削除、重複・未登録 URL、検索除外ヘッダー、連絡先の文字のみ・template 内リンク、JS 注入、canonical 誤り、未設定の顧客テンプレートをテストする。CLI の模擬配信と実公開先も検査し、ローカル検証と main 上の定期実行を区別して status.md に記録する。

## 公式仕様の参照（2026-09-18）

- [Google: robots meta と X-Robots-Tag](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag): HTML と HTTP の両経路で検索除外が指定されうるため、両方を見る。
- [GitHub: schedule](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule): 定期実行は既定ブランチが対象で遅延しうる。ブランチ上の実装完了だけで本番の定期監視が直ったと扱わない。
