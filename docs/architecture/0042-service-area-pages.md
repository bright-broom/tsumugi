# 0042 対応エリアのページは、実際に対応し固有の本文がある市区町村だけ公開する

- 状態：採用（2026-09-16）
- 関連：[#18](https://github.com/bright-broom/tsumugi/issues/18)、[0040](0040-collections.md)

## 問題

市区町村別のページは、地名だけを差し替えた同じ文章を量産しやすい。検索の評価を下げ、実際には対応していない地域への問い合わせを生む。現在の `AREA` は「全国」という表示用の文字列で、地域の構造化データはない。

## 決定

- 1 件は、都道府県・市区町村・対応可否（`available` / `partial` / `unavailable`）・一部対応の条件（`serviceNote`）・その地域に固有の本文・SEO 情報を持つ。
- 公開前チェックで次のどれかに当たると、公開にした項目はビルドを止める。
  - 対応外（`unavailable`）。対応外の地域は下書きのまま記録だけする
  - 一部対応なのに条件が空
  - 本文から市区町村名と都道府県名を除いた文字数が 120 字未満
  - ほかの公開中の地域と、地名を除いた本文の文字 3-gram の Jaccard 係数が 0.8 以上（地名の差し替えだけのページ）
- 一覧（`/areas.html`）は都道府県ごとに市区町村のリンクを並べ、一部対応を併記する。詳細（`/areas/<slug>.html`）は対応状況・本文・問い合わせ導線（電話と相談ページ）を出す。
- ルート・canonical・sitemap（`lastmod` 付き）は他のコレクションと同じ仕組み（[0040](0040-collections.md)）。地域を足すとページと sitemap の行が増え、下書きに戻すと両方から消える。
- slug は県名を含めて一意にする（例：`hyogo-sumoto`）。同名の市区町村が別の県にあるため。

## 閾値について

120 字と 0.8 は、実データを持たない段階で置いた目安。最初の顧客の文書で誤検出や見逃しがあれば、理由を添えてこの ADR を更新する。閾値を下げて通すのではなく、まず本文を地域に固有の内容にする。

## 紬の自社サイト

紬は地域ページを作らない（データは空）。`config.ts` の `AREA` の表示は変えない。

## 検証

架空のフィクスチャで、一部対応の表示、都道府県ごとの一覧、問い合わせ導線、対応外・短い本文・地名の差し替えだけの本文の停止、追加と削除によるルートと sitemap の増減をテストする（`tests/collections.test.tsx`）。
