# 0080 記事・事例を microCMS から取り込んで静的に公開する

- 日付：2026-09-19
- 状態：採用（実サービスでの確認は未実施。main 反映は status.md 参照）

## 背景

監査 C01。「情報を育てる」プランは「記事・事例の更新管理画面」「初期登録 3 件と操作説明」「共通構成を使う標準 CMS」を約束しているが、管理画面がなく受付準備中だった。料金資料は CMS をお客様名義の外部サービス（無料枠・有料枠）として試算し、候補に microCMS を挙げている（2026-09-18 に公式料金を確認）。2026-09-19、オーナーは受付準備中の商品も実装するよう指示した。記事・事例のしくみ（型付きのブロック、寸法付きの画像、公開前チェック）はすでにあり、データはリポジトリの TypeScript に書く前提だった。

## 判断

microCMS を「取り込み元」として追加する。公開サイトの作り方（静的出力・実行時 JS 0・自サイトの画像だけ）は変えない。

- `tools/cms/pull.ts`：ビルドの最初に、`CMS_SOURCE=microcms` のときだけ公開済みの記事・事例を取得し、既存の公開前チェックを通してから、スナップショット `src/i18n/locales/ja/entries/cms.json` と画像 `public/images/cms/` を書き出す。未設定なら何もしない（紬の自社サイトはこの状態）。チェックに通らなければビルドを止め、公開中の版を残す。
- 本文は HTML を受け取らず、繰り返しフィールドのカスタムフィールド（段落・見出し・リスト・画像）で受け取り、既存の型付きブロックへ変換する（監査 D11 の XSS の懸念を CMS 入力に持ち込まない）。
- 画像は `images.microcms-assets.io` のものだけを受け付け、microCMS の画像 API で WebP・最大幅 1600px にしてから取り込む。ファイル名は元の URL と幅から決め、使わなくなった画像は消す。
- 業種・分類・地域の定義はリポジトリに残す。CMS からは記事・事例の中身だけを受け取る。
- 更新はお客様が microCMS で公開 → Webhook → Vercel の Deploy Hook で再ビルド。失敗時の再実行は Webhook の再送か再配備。
- スナップショットと画像をコミットしておけば、CMS を解約しても同じサイトを作り直せる（所有の方針）。

SDK を依存に加えず、microCMS の REST API（一覧・ページ送り・API キー）を直接使う。

## 限界と未決

- 下書きのプレビュー、承認フロー、変更履歴は microCMS 側の機能（プランによる）に任せ、サイト側では提供しない。
- CMS への書き戻し（復元）は未実装。
- 実際の microCMS サービス・Webhook・Deploy Hook では未確認。料金プランの選択と規約は導入時に確認する。
- `prices.ts` の「情報を育てる」の `preparing` は変えていない。最初の導入で公開・更新・削除・失敗時の保持を確かめ、操作説明を渡せる状態になってからオーナーが受付を開始する。
