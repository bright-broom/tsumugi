# 0084 日付で表示が変わる日に、静的サイトを作り直す

- 日付：2026-09-24
- 状態：採用（配備フックの設定と実際の作り直しは、臨時の案内を使うサイトが出てから）

## 背景

監査 C08「日付で変わる営業時間等を静的出力へ反映する再生成の運用がない」。

臨時休業・臨時の営業時間（`HoursException`）は、ビルドした日（`STORE_AS_OF`）を基準に、終わったものを表示と JSON-LD から外している（[ADR 0048](0048-storefront-template.md)）。**静的なサイトは置いたままでは変わらない**ので、年末年始の休業が明けても「臨時休業 12/29〜1/3」が出たままになる。閲覧者は営業しているのに閉まっていると読み、検索結果の構造化データも古いままになる。

## 判断

- `npm run refresh`（`tools/ops/freshness.ts`・`cli/refresh.ts`）が、**前回（既定は前日）から今日までに表示が変わる境目**を出す。境目は 2 つだけ：案内が**始まる日**と、案内が**終わった翌日**（表示から外れる日）。期間の途中では作り直さない。
- 境目があれば終了コード **10**、無ければ 0、判定に失敗したら 2。ワークフロー `daily-refresh.yml` が日本時間 0:10 に実行し、10 のときだけ Vercel の配備フック（シークレット `VERCEL_DEPLOY_HOOK`）を叩いて作り直す。
- **境目が無い日は何もしない**。毎日の空振りで通知を出すと、本当に必要な日の通知が埋もれる。
- 境目があるのに配備フックが未設定なら、ジョブを失敗させて気づけるようにする（臨時の案内を使わないサイトでは、そもそも境目が出ないので失敗しない）。

判定はサイトの内容（`src/content/store.ts`）だけから決まる純粋関数に置き、通信と配備はワークフローに置く。

## 限界

- **作り直しの完了までは見ていない**。配備フックは要求を受け付けるだけで、反映は Vercel の配備の完了後。配信内容が main と一致するかは Release check（[ADR 0076](0076-release-drift-check.md)）が別に見る。
- 紬の自社サイトは臨時の案内を持たないので、この仕組みは常に「境目なし」で終わる。実際の作り直しは、臨時の案内を使う顧客サイトで初めて動く。
- 営業時間そのものの変更（毎週の時間を変えた）は、コードの変更＝配備なので対象外。
- 日付は店舗の時間帯（`STORE.timeZone`）の暦日で扱う。複数時間帯の拠点を持つサイトは想定していない。
