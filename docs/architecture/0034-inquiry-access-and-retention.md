# 0034 — 問い合わせ情報への権限・履歴・保持期限・削除を、窓口とデータで管理する

日付：2026-09-16。状態：採用（認証基盤と本番の履歴保存先は未決）。関連：[#33](https://github.com/bright-broom/tsumugi/issues/33)、[0032](0032-inquiry-intake-service.md)、[0033](0033-dual-notification-and-reply-deadline.md)。

## 背景

プライバシー表示（`i18n/locales/ja/privacy.ts`）は「担当する2名以外がアクセスできない場所に保管」「ご契約に至らなかった場合は1年で削除」「契約終了後は法令で定められた期間（帳簿等は7年）保管」「開示・訂正・削除・利用停止のお求めに応じる」と約束しているが、保存先・権限・期限管理・削除処理の実装がなかった。

## 決定

### 情報の所在

受付・通知・履歴・バックアップ・配備先のログ・担当者の端末に何が残るかを [docs/inquiry-data.md](../inquiry-data.md) に一覧にし、削除の手順と、この処理で消えないもの（通知メール・バックアップ）を明記する。

### 担当者と権限

- 担当者は `content/inquiry.ts` の `INQUIRY_STAFF` にデータで持つ。実名・連絡先は置かず、短い ID と役割だけにする。
- `validateRoster` が、有効な担当者が 1〜2 名（`MAX_STAFF_WITH_ACCESS = 2`）であること、ID が重複せず個人情報に見えない形であること、管理者が 1 名以上いることを検査する。退任した担当者は `active: false` で記録に残せる。
- 役割は `administrator`（閲覧・更新・保持期限の管理・履歴の閲覧）と `responder`（閲覧・更新）。割り当ては仮置きで、オーナーが決める。
- 問い合わせ情報を読む・変える・消す操作は `createInquiryDesk` の窓口だけを通す。操作の前に、許可・拒否のどちらも履歴に書き、**履歴を書けなければ操作しない**。

### 閲覧・変更の履歴

- `AccessLog` インターフェース（`append`・`list`）。記録するのは時刻・担当者 ID・権限・操作・対象の受付番号・結果（allowed / denied / refused / failed）と、理由の区分や件数だけで、問い合わせの内容や連絡先は書かない。テストで確かめている。
- 実装はテスト用のメモリ版だけ。本番は追記専用の保存先で実装する。

### 保持期限と削除

| 記録 | 削除してよくなる時刻 |
|---|---|
| 非契約（`prospect`） | 最後のやり取り（受付・初回返信・契約状態の記録のうち最も新しい時刻）から 1 年 |
| 契約中（`contracted`） | 削除しない |
| 契約終了（`ended`） | 終了日から 7 年 |
| 迷惑投稿の疑い | 受付から 30 日 |

- 期間は `INQUIRY_RETENTION` にデータで持ち、プライバシー表示の「1 年」「7 年」「2 名」と一致することをテストで確かめる。
- 法的な保全（`legalHold`）がある記録は、期限を過ぎても削除せず「例外」として履歴に残す。
- 削除はまずドライランで対象・例外・残す件数を確認し、次に実行する。削除できなかった記録はエラーとして記録し、残りの削除を続ける。どちらも件数と受付番号だけを履歴に残す。
- 担当者の操作は窓口の `runRetention`（管理者のみ）。定期実行はスケジューラ用の ID で `runRetention` を直接呼び、担当者の枠（2 名）を使わない。
- ご本人からの削除のお求めは窓口の `erase`。契約中・契約終了後の保管期間内・法的な保全中の記録は削除せず、理由（`contract-retention`・`legal-hold`）を履歴に残して返す。

## プライバシー表示との照合（文言は変更していない）

一致させたもの：必須 3 項目と取得する 6 項目、2 名に限定、非契約 1 年・契約終了後 7 年、削除のお求めへの対応、第三者に提供しない（通知は委託の範囲）。

実装だけでは一致を保証できず、判断が必要なもの（[docs/inquiry-data.md](../inquiry-data.md) に詳細）：

1. 「1年で削除」の起点が表示に書かれていない。実装は「最後のやり取りから 1 年」とした。
2. 通知で送ったメールの複製、バックアップ、配備先のアクセスログは、削除処理では消えない。表示にはバックアップとログの保持の記載がない。
3. 「業務の委託」は「フォームの送信・保管」とあるが、メール・LINE・SMS の通知事業者を含むことが明示されていない。
4. 迷惑投稿の疑いを 30 日保存することは表示にない（1 年より短いので約束には反しない）。
5. 契約終了後 7 年は「帳簿等」の期間で、問い合わせ内容そのものを 7 年保つ必要があるかは確認が要る。
6. 「端末には画面の自動ロックと暗号化」はリポジトリから確認できない。
7. 「アクセス解析も Cookie も使っていない」は受付サービスでも守っている（Cookie を発行せず、IP アドレスを保存しない）が、配備先の事業者が記録するリクエストログは別途確認が要る。

## 今回の境界

担当者 ID と実際の認証基盤（アカウント・二要素認証）との対応、本番の履歴保存先、バックアップの保持期間、通知メールを削除する作業の実施は含めない。
