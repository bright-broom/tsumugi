# 0043 顧客事例は、測定期間・出所・掲載許可の記録と一緒に持つ

- 状態：採用（2026-09-16）
- 関連：[#38](https://github.com/bright-broom/tsumugi/issues/38)、[0040](0040-collections.md)。`works.html` の文言と実測値の表示は #34・#40 の担当

## 問題

`works.html` は「顧客事例は、掲載許可をいただいたうえで、実際に計測できた数字を掲載する」と約束している。事例を足すデータ構造がなく、足したときに未計測の値を 0 や成功のように見せない仕組みもなかった。

## 決定

### 測定値

- 1 つの値は「測った」（数値・測定期間の開始日と終了日・出所）か「測っていない」（理由）のどちらか。**既定値を持たない**ので、入力を忘れた値が 0 として表示されることはない。
- 項目は表示速度（LCP）・Googleビジネスプロフィールの閲覧数・問い合わせ・予約・費用。項目名と単位はカタログ、何を数えたか（例：ポータルの月額掲載費）は項目ごとの `note` に書く。
- 公開前と公開後の両方を測った項目だけ差を出す。差は符号付きの数字だけで、「改善」「成功」などの評価語を付けない（表示速度は小さいほど良く、費用は目的で解釈が変わるため）。
- 公開後の期間は、公開前の期間が終わってから始まること。出所が空、終了日が開始日より前、未計測の理由が空なら公開できない。
- 数値にならない確認済みの結果（`outcomes`）と、うまくいかなかったこと（`setbacks`）を持つ。`works.html` が掲載を約束している項目。

### 掲載許可

- `permission` に状態（`granted` / `pending` / `declined`）・確認日・確認の方法と記録の保管場所・範囲（名前・数値・画像・URL・本文）を持つ。`granted` と確認日と方法がそろわなければ公開できない。
- 表示する要素ごとに範囲を確かめる。範囲に「名前」がなければ「お名前は掲載していません」と出し、数値・画像・URL・本文も範囲にないものは公開前チェックで止め、表示側でも出さない。
- **リポジトリは Public** なので、許可書の原本・担当者の氏名・連絡先はここに入れない。`method` には「署名済みの許可書（社内の保管場所）」のように、所在だけを書く。

### 表示

- `works.html` には、公開中の事例が **1 件以上あるときだけ**「掲載許可をいただいた顧客事例」の区画を足す。0 件の間は現在の説明をそのまま出す（HTML は変更前と同じ）。
- 詳細は `/works/<slug>.html`。共有画像は既存の `og/works.png`。一覧は作らず、`works.html` に添える。

## 残したこと

- 事例が 1 件になったとき、`works.html` の見出し「現在の制作事例は、このサイトです」などの文言は実態と合わなくなる。文言は #34・#40 の担当範囲なので、ここでは区画の追加だけにとどめた。最初の事例を公開する前に文言をそろえる。
- 実案件の測定と掲載許可の取得は、機能とは別の作業（#38 の「実績待ち」）。

## 検証

架空のフィクスチャで、未計測の表示（0 にならない）、測定期間と出所、差の算出条件、確認できた結果とうまくいかなかったこと、許可の状態と範囲による停止と非表示、区画が 1 件以上のときだけ出ることをテストする。
