# 0021 料金の読み順と和欧文の表記を揃える

- 日付：2026-09-15
- 状態：採用

## 判断

比較表の各行に繰り返していた「制作費＋保守月額＋外部費月額」を、制作費と期間総額の2段にする。ホーム・料金ページで同じi18nの文言を使い、保守と外部費を総額に含む条件は共通の注記から表示する。制作費・月額・税・36か月の総額を計算する `content/prices.ts` は変更しない。負けている比較も保持する。

ホーム後半は、制作に含む5項目と別途必要な3項目をアイコン付きの一覧にし、受付準備中の9ページプランの金額・状態を分けて示す。比較は2つの総額と差額を先に表示し、全ページ数の比較表と出典はネイティブのdetails内に置く。図解4点を保持し、所有時期の図から月額の重複表記を外す。制作プランの見出しに金額を重ねず、プラン本体で確認できるようにする。増築の充当条件は料金ページを正本として案内する。

アイコンは既存のLucideを使い、共通のTailwind CSSで配置する。HTML内のSVGにはブラウザが名前空間を与えるため、アイコンごとのxmlns属性を省き、追加アイコンの容量を抑える。SVGファイルや図形の座標、読み上げの指定は変えない。

## 和文と英数字の半角スペース

`i18n/typography.ts` に日本語とASCII英数字の間へリテラルの半角スペースを入れる規則を置く。カタログを解決するときと、名前付き変数を差し込む `format` の最後に同じ規則を適用する。Statsの数値と単位も共通規則を使用する。別の要素で表示する通貨単位はカタログ側に先頭の半角スペースを持つ。

HTMLを含むカタログでは `parse5` を使い、テキストと案内属性だけを元の文字位置に差し戻す。HTML全体の正規表現置換は行わない。URL・メール・コード・スクリプト・フォーム値・SVG座標等を保護し、文章内のstrong等をまたぐ境界にも対応する。整形は冪等で、繰り返し適用してもスペースが増えない。

SSR後だけのHTML書き換えは採用しない。開発時にReactが再描画する文字と一致しなくなるためである。最初から表示用文字列を揃え、postbuildでは未適用のテキスト・案内属性が残っていないことを検査する。要素間の余白はレイアウトにより異なるので、公開HTML全体の検査ではインライン要素を機械的に連結しない。公開用の実行時JSは0バイトを維持する。

補助金の図で日本語日付を短くする処理は、スペースの有無によらず同じ月日を取り出すようにした。表示の変更で日付や計算の意味が変わらないことをテストする。共有画像21枚も同じ規則で再生成する。
