# 0082 引渡し資料を 1 つに梱包し、作り直せたことを確かめてから封をする

- 日付：2026-09-24
- 状態：採用（架空の顧客での通し確認まで。ビルドまでの再現確認は、この作業環境では実行できない）

## 背景

監査 D06「引渡しは参照記録中心。必要資料の梱包・アクセス権・移管後再現性の一括証跡がない」。

CRM（ADR 0038）は引渡しを「ソースコード一式・引き継ぎ手順書・写真の元データ・GitHub の閲覧招待」の 4 点の**参照**として記録できたが、次の 3 つが抜けていた。

- **梱包**：実際に何を渡したのかが残らない。渡した資料が後から変わっても分からない。
- **名義とアクセス**：ドメイン・ホスティングがお客様名義かどうか、紬のアクセスを撤回したかどうかを、案件の記録として持っていなかった（納品チェックの「ドメインがお客様名義」は 1 行の確認だけ）。事業の規範は「お客様が自分でサイトを持ち続けられること」を約束している。
- **移管後の再現性**：渡したソースから、別の環境でサイトを作り直せるかを確かめていなかった。バックアップの復元テスト（ADR 0045）は自社のバックアップにだけ使っていた。

## 判断

`npm run ops:handover`（`tools/ops/handover/`）を追加し、引渡しを 4 段階にする。

1. **plan**：引き渡せる状態かを見る。検収済み・納品チェック完了・ドメインとホスティングがお客様名義・全項目の検査が FAIL 0。
2. **pack**：1 つのフォルダに梱包する。
   - `source/`：`git bundle`（履歴ごと）＋ファイルごとの SHA-256 の目録（ADR 0045 の `createBackup` をそのまま使う）
   - `materials/`：写真などの元データ（`--material`）
   - `handover.md`・`handover.html`：お客様向けの引渡し書（同梱物・名義とアクセス・検査の実績・別の環境で作り直す手順・連絡先）
   - `handover.json`：同じ内容の機械可読な記録
3. **verify**：同梱のバンドルを別のフォルダへ取り出し、目録と突き合わせ、依存を入れ直してビルドまで通す（ADR 0045 の `restoreTest`）。通ったときだけ `SHA256SUMS` で**封**をする。
4. **record**：封のある資料だけを CRM の引渡し記録にする。そろえば「引渡し済み」に進められる。

あわせて、CRM の案件に**アカウント**（種類・サービス・名義・名義の確認日・紬のアクセスと撤回日／保持の理由）を記録し、ドメインとホスティングがお客様名義になるまで「引渡し済み」にしない。

### 決めたこと

- **封の条件はビルドまでの再現**。引渡し書に「別のフォルダで作り直せることを確かめた」と書く以上、`--build build`（依存を入れ直してビルド）を通した確認だけを封にする。型検査まで・ビルド省略の確認では封をしない。
- **認証情報は記録も同梱もしない**。アカウントの参照・備考は「管理画面の名前」までにし、パスワード・鍵・トークンらしき文字列は記録の時点で拒否する。元素材も、`.env*`・鍵ファイル・秘密情報の形を見つけたら梱包しない。ログイン情報は資料とは別の経路で渡す。
- **検査の実績は流用しない**。引渡し書に載せる PASS・WARN の件数は、全項目・FAIL 0・**引き渡すコミットと同じ**・未コミットの変更なしのレポート（ADR 0025 の `adoptReport`）からだけ取る。静的検査だけのレポート、別のコミットのレポートは拒否する。
- **封は資料全体を覆う**。`SHA256SUMS` は `handover.json` 自身も含める。中身が 1 バイトでも変われば `record` が止まる。
- **上書きしない**。同じ日の資料が既にあれば作らない。途中で止まったときは作りかけを消す（渡した資料を同じ場所で黙って作り替えない）。

## 限界

- **ビルドまでの再現確認は、この作業環境では実行できない**。サンドボックスが別フォルダでの `npm` の起動を許さない（`spawnSync npm EPERM`）。チェックサムの照合・別フォルダへの取り出し・目録との突き合わせ（528 ファイル・5,076,576 バイト）までは実機で通っている。封はオーナーの環境か CI で行う。
- 同じ理由で、引渡し書に載せる検査の実績も、この環境では作れない（ブラウザ計測が動かない。ADR 0047 と同じ制約）。架空の顧客での通し確認には、実測ではないと分かる見本のレポートを使い、資料は作業後に消した。
- アカウントの記録は自己申告で、登録事業者の画面と自動で突き合わせてはいない。
- 元素材の中身（写真が正しいか）は見ていない。見ているのは「入れてはいけないものが入っていないか」だけ。
