# 0030 ヒーローの文字分離と中央管理を検査で固定する

- 日付：2026-09-16
- 状態：採用（Issue #36 の完了判定）

## 問題

ADR 0019 で背景画から文字を除き、見出し・本文・代替説明を `i18n/locales/ja/home.ts` の `hero` から描画するようにした。ただし検査は「差し替えたコピーが HTML に出る」1 件だけで、次の点は仕組みとして守られていなかった。

- 背景画の SVG に文字要素やコピーが入り込んでいないか（SVG の組み立ては `build-public.ts` の中にあり、テストから呼べなかった）
- 承認済みの絵が、文字入りの別画像に差し替わっていないか
- 同じ文字列が見出しと代替説明などで重複し、読み上げで二度読まれないか
- 狭い画面でコピーが画像の外に出ていないか（#60 で修正）

## 判断

- SVG の組み立てを純粋な関数 `heroSvg(artworkAlt, webpBase64)` として `content/hero.ts` に移し、`build-public.ts` とテストが同じ関数を使う。生成される `images/onokoro-hero.svg` はバイト単位で変わらない。
- `tests/content-routing.test.tsx` に次の検査を足した。
  - **コピー変更だけで全表示が同期する：** カタログの 5 項目を差し替えると、HTML の見出し・本文・`alt` と SVG の `<title>` がすべて差し替え後の文字列になり、元の文字列が残らない。各文字列はページ内でちょうど 1 回だけ出る。
  - **背景画に文字がない：** SVG に `<text>`・`<tspan>`・`<foreignObject>`・書体指定がなく、`<title>` は絵の説明 1 つだけで、見出し・本文を含まない。ラスター画像の中の文字は機械では判定できないため、承認済みの `onokoro.webp` の SHA-256 を固定し、差し替え時に目視確認とテストの更新を必須にする（`src/assets/hero/README.md`）。
  - **二重読み上げがない：** ヒーロー区画の `h1` は 1 つで `aria-labelledby` が指し、`aria-hidden`・`aria-label`・装飾用の複製・インライン SVG を持たない。代替説明は見出し・本文の文字列を含まない。
- 画面上の欠け・切り取りは #60（ADR 0029）の実測で確認した。

## #36 の完了条件との対応

| 完了条件 | 判定 | 根拠 |
|---|---|---|
| 承認済みの絵と表示文字を別の要素にする | 満たす（ただし絵は暫定） | 背景画は文字のない WebP を内包した SVG、コピーは HTML。現在の絵を最終素材として採用するかはオーナーの判断待ち（`docs/status.md`「ヒーロー画像の本採用」） |
| 画像上のコピー・HTML 見出し・代替説明を同じカタログから生成する | 満たす | `home.ts` の `hero` だけが正本。上記の同期テスト |
| PC / モバイルで文字の欠落・二重読み上げ・切り取りがない | 満たす（読み上げは構造の検査のみ） | 二重読み上げのテスト。320〜1920px と 200% ズームで全文が画像内に収まることを実測（ADR 0029）。VoiceOver などの実機の読み上げは未確認 |
| コピー変更だけで全表示が同期することを検査する | 満たす | 上記の同期テスト |

コードで閉じられる範囲は完了と判断する。Issue を閉じる前に、オーナーによる背景画の本採用と、実機での読み上げ確認が残る。
