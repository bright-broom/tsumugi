# 0071 — 公開HTMLが直接参照するCSS・画像を監視する

日付：2026-09-18。状態：採用。関連：#32、監査A06、ADR0064/0069。

## 背景と判断

ページ本文と配信ヘッダーが正常でも、CSSや画像だけが消えると従来の監視は成功する。顧客の連絡先や価格を読めなくする障害を早期に検出するため、公開監視と公開直後検査へ参照資産の確認を追加する。

## 対象と方式

- トップ`/`と取得できた各公開HTMLから、parse5でstylesheet、imgのsrc、アイコン、og:imageを収集する。template内は配信中の画像と扱わない。
- 相対URLをページURLから解決し、クエリを保持、フラグメントを除いて重複をまとめる。同じURLをCSSと画像の両方で使っていたら、両方の期待型を検査する。
- 同一originのみへHEADを送る。認証情報付きURLはFAILで取得せず、外部サイトやdata等は対象外参照として件数を示す。URLの認証情報をログへ出さない。
- HEADが転送なしの200であり、CSSはtext/css、画像はimage/*であることを検査する。404/5xx/転送/405/通信エラー/型欠落・不一致をFAILにし、他資産の確認は続ける。HEAD非対応の公開先もPASSにしない。
- 最大128資産。上限を超えたら資産通信の前にFAIL。最大4並列、各要求15秒のタイムアウト、レスポンス本文は読まずキャンセルする。
- 200ページなし、検査可能な同一サイト資産なしもFAIL。通信しない`--dist`は同じ検査でファイル欠落・種別を判定するが、DNS/TLS/実配信ヘッダーの証明にはしない。

## 限界

HEADは本文の完全性・描画成功を証明しない。全バイト照合はcheck:release、実画面の確認はverifyを併用する。CSS内部のurl()/import、SVG内部参照、srcset/pictureの候補、外部資産は今回の対象外。これらまで網羅した成功とは表示しない。画像のサイズ・内容・デコード結果、監視停止・通知到達・Search Consoleも別の確認として残る。

## 検証

相対URL/クエリ/重複、404/503/302/405、ソフト404・MIME欠落/不一致、外部/data/template、認証URL、型の競合、検査対象なし、上限・並列数、トップ別名と通常ページでのCLI共通経路を故障注入で確認する。全体・実通信・模擬配信の結果はstatus.mdに記録。公開ページ・価格・CSS・依存パッケージは変更しない。
