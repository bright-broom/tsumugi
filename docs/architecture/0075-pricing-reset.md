# 0075 — 料金を用途・作業範囲・実費に整理する

日付：2026-09-18。状態：採用・本番反映前。価格と提供範囲について0011/0049の旧金額を置き換える。0050の制作のみ・任意支援の方針は維持。

## 背景

ユーザーから費用監査を踏まえた料金再設定の依頼。旧価格は短い工数仮定、撮影・ロゴ等の範囲の曖昧さ、予約リンクと設定の重複、外部費の仮置きが課題だった。監査の値上げ案を一括採用するのではなく、[新料金表](../business/pricing-2026-09-18.md)として整理した。

## 決定

- 制作10万/25万/45万円、任意支援0/6千/1.2万/3万円。税別。既存契約・有効な見積もりへ遡及しない。
- 追加8種は対象量と確認回数を定義。予約リンクは基本内、予約設定は3万円、独自API開発は別。写真とロゴは参考価格から個別見積もりとする。
- 月額保守に無制限復旧を含めない。営業時間内の一次切り分けは月30分、復旧は事前見積もり。紬の仕様不適合の修補は別途請求しない。
- 外部費3,500円は比較用仮定として保持し、紬の固定料金として表示・請求しない。実際の請求内訳を別途確定する。
- 準備中CMS・多言語、検討中の上位商品はその状態を保つ。概念商品の参考額の整理だけで受付を始めない。
- 社内モデルの既定構成からCMSを外し、全本人時間控除後の不足と複合ストレス時の超過も表示。固定費等の未知を安い値へ置換して採算を作らない。
- 旧監査と上位提案は履歴表示し、新料金・2冊のExcel・現行ガイドを同期する。金額の正本はprices.tsのみ。月次変更ページの追加ページ料金もこの正本から生成する。

共通フロントエンドガイドを参照し、既存の静的React/TypeScript・Lucide・料金表を再利用。新規依存、UI部品、アニメーションの採用なし。

## 検証

価格と社内モデルの同期、総額・税込・支払分割、未提供商品の見積拒否、個別見積区分、既存見積の保持を既存テストで確認する。型・lint・ビルド・静的/本番モード検査、狭幅/広幅の価格ページ、Excel再計算を実施し、結果はstatusへ記録する。需要・実工数・実請求は未検証。

## 自社公開判断の継続

対象はADR0056と同じ紬自社サイト・同じ事業者・同じ電話/メール受付。今回の「料金設定をしてください」という明示依頼に含まれる料金と対応範囲の改定に合わせ、規約の保守範囲と公開判断の対象ハッシュを更新する。既存の公開指示を継続し、専門家確認・顧客納品検収の完了とは扱わない。LEGAL_APPROVALS/ACCEPTANCE_RECORDS、未確認項目の一覧は変更しない。有料サービス契約・実送信を追加で行う根拠にはしない。

検査時にPlaywrightの文字列waitForFunctionがscript-src noneのCSPで失敗したため、同じCSS読込条件を検査側の期限付きポーリングで確認する。ページのCSPや本番出力は緩和せず、5秒以内に読めない場合は従来どおり失敗させる。
