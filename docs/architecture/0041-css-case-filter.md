# 0041 事例の絞り込みを JavaScript なしの CSS で行う

- 状態：採用（2026-09-16）
- 関連：[#17](https://github.com/bright-broom/tsumugi/issues/17)、[0040](0040-collections.md)
- 制約：公開ページの実行時 JavaScript 0 バイト

## 問題

プロプランの事例一覧は「業種・分類・地域を組み合わせた絞り込み」と「0 件のときの表示」を約束している。実行時の JavaScript を使わずに実現する方式を選ぶ。

| 方式 | 良い点 | 問題 |
|---|---|---|
| 条件ごとの一覧ページを事前生成 | どのブラウザでも動く・URL で共有できる | 複合条件で組み合わせが掛け算で増える。中身が少しずつ違うだけのページが量産され、sitemap と検査の対象も膨らむ |
| **CSS（`:checked` と兄弟セレクタ、0 件表示だけ `:has()`）** | 1 ページで完結・複合条件も規則が増えない | 状態が URL に残らない。古いブラウザでは 0 件表示が出ない |

CSS を採用する。

## 仕組み

```html
<form class="cf">
  <input class="cf-radio cf-f1-v0" type="radio" checked> … 全ファセットのラジオ
  <div class="cf-controls"> label[for] の選択肢と <button type="reset"> </div>
  <ul class="cf-list"> <li class="cf-item cf-i1-v2 cf-i2-v1 cf-i2-v3"> … </ul>
  <p class="cf-empty">条件に合う事例はありません…</p>
</form>
```

- クラス名は位置で決める。`cf-fN-vM` はファセット N の値 M（0 は「すべて」）、`cf-lN-vM` はその選択肢、`cf-iN-vM` はその値を持つ項目。規則は `src/styles/collections.css` に固定で書き、データに合わせて CSS を生成しない。
- 絞り込み：`.cf-f1-v2:checked ~ .cf-list > .cf-item:not(.cf-i1-v2) { display: none }`。ファセットをまたぐと AND、1 つのファセットの中では 1 つを選ぶ。項目が複数の分類を持つ場合は、そのどれかに合えば残る。兄弟セレクタだけなので、`:has()` のない環境でも動く。
- 条件を戻す：フォームの `<button type="reset">`。ブラウザ標準の動作で、すべてのファセットが「すべて」に戻る。
- 0 件表示：`:has()` の中の `:is()` に兄弟結合子を書き、「選択に合う項目が 1 つでもあるか」を 1 つの規則で判定する。`@supports selector(:has(:is(a ~ b > c)))` の中にだけ置くので、対応しないブラウザでは表示されない（絞り込みは動き、何も出ないだけになる）。
- データが使わないファセットの枠にも、隠した「すべて」のラジオを置き、0 件判定の規則を常に満たせるようにする。
- 選択肢は公開中の事例が使っている値だけから作る。値が 1 つしかないファセットは出さず、ファセットが 0 個なら絞り込みのない一覧にする。
- `lib/collections/cases.ts` の `matchesSelection` が CSS と同じ意味の参照実装で、テストが両者の対応（上限の規則の有無を含む）を確かめる。

## アクセシビリティ

- ラジオは視覚的に隠し、`label` を 44px 以上の押し面にする（`verify` のタップ領域検査が、隠した入力に対応する label を測る）。キーボードの矢印でファセット内を移動でき、フォーカスは対応する label に表示する。
- 選択肢の文字「すべて」はファセットごとに繰り返すため、各ラジオに分類名を `aria-describedby` で添える。

## 制約（受け入れたこと）

- 上限は **3 ファセット × 各 12 値**（`FILTER_LIMITS`）。超えるとビルドが止まる。上げるときは CSS の規則を足し、テストを通す。
- 選択状態は URL に残らない。共有・ブックマーク・再読み込みで条件は戻る。条件ごとの URL が必要になったら、条件を絞った事前生成ページを別途足す（その場合は `noindex` か canonical を一覧に向ける）。
- 表示件数は読み上げられない。JavaScript がないとライブリージョンを更新できないため、0 件のときの文を出すだけにする。
- 1 つのファセット内での複数選択（OR）はしない。規則が組み合わせで増えるため。
- ページ分割はしない。事例が増えて HTML の 100 KiB 予算に近づいたら、業種別の一覧ページに分ける。

## 検証

架空のフィクスチャで、選択肢の生成（下書きだけが使う値を出さない）、入力・操作部・一覧・0 件表示の並び順、項目のクラス、`type="reset"`、上限超過の停止、追加・更新・非公開を単体テストで確認する。

2026-09-16 に、同じフィクスチャの事例一覧をビルド済みの `theme.css` とともに Chromium（Playwright 1.63、headless shell）で開き、幅 390px と 1280px で操作した（リポジトリには含めない一時スクリプト）。

| 操作 | 結果（390px・1280px とも） |
|---|---|
| 初期表示 | 3 件表示・0 件表示は非表示 |
| 業種を選ぶ → 分類を足す | 2 件 → 1 件（AND） |
| 合う事例がない組み合わせ（業種×分類、業種×地域） | 0 件・0 件表示が出る |
| 条件を戻す（`type="reset"`） | 3 件に戻り、0 件表示が消える |
| キーボード（矢印キー） | 選択が移り、対応する label にフォーカス枠 |
| 押し面・横スクロール | 最小 44px・横スクロールなし |

`:has()` を持たないブラウザでの表示（0 件表示が出ないこと）は実機で確かめていない。
