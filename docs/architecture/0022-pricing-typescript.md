# 0022 — 料金モデルも TypeScript の検査対象に含める

日付：2026-09-15。状態：採用。関連 Issue：[#56](https://github.com/bright-broom/tsumugi/issues/56)、改善計画 [#55](https://github.com/bright-broom/tsumugi/issues/55)。

## 背景

アプリと開発ツールは TypeScript に移行していたが、後から追加した `tools/pricing/` のモデル・レポート・テストだけが `.mjs` で残っていた。`allowJs: false` は JavaScript を型検査から除外する設定なので、この 3 ファイルには既存の strict な型検査が働いていなかった。

## 決定

- モデル・レポート・テストを `.ts` に移し、料金、工数、計算条件、プランごとの件数に明示的な型を付ける。既存の `tools/**/*.ts` の型検査に含め、検査対象外の例外は作らない。
- 管理下の `proposal.json` を JSON import で読み、入力フィールドの欠落や型の違いをコンパイル時にも確認する。任意の外部 JSON を受け付ける機能は追加しない。
- 実行は既存の `tsx` に統一する。`npm run test:pricing` は Node のテストランナーを継続使用し、`npm run --silent report:pricing` は JSON だけを標準出力へ出す。追加パッケージは不要。
- Knip は package.json の実行入口からレポートを発見する。手動の重複した入口指定と `.mjs` 用のプロジェクト設定を取り除く。
- 構造検査で、ルートのコードファイルと `src/`・`tools/`・`config/`・`tests/` 内にある `.js`・`.mjs`・`.cjs`・`.jsx` を拒否する。生成物・依存パッケージは別扱いとし、公開時の JavaScript 0 バイト検査も維持する。
- 型検査で明らかになった「制作プランに対応する比較先月額がない」入力は、比較結果を `NaN` にせず `RangeError` にする。通常の計算式と既存の入力値は変えない。

公開料金の正本は引き続き `src/content/prices.ts`、このモデルは経営仮定を検証する独立したツール。公開サイトがモデルを読み込む依存は追加しない。

## #56 の残りを扱う境界

手書き JavaScript の解消と、React への画面構造の移行は別の単位で検証する。後者は次の棚卸しを起点に進める。

| 現在の経路                                                                                              | 後続の置換方針                                                                                                                          |
| ------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `src/content/diagrams.ts` が figure / SVG の文字列を生成し、`Figure.tsx` が正規表現で外枠を取り出す     | 図形の構造は `components/` の型付き React / SVG、文字は i18n、事業データは content に分離する。content から components を import しない |
| `Flow`・`Table`・`Section`・`Calc`・`Note`・`Acc`・`Cards` と一部 views が `raw()` で装飾本文を描画する | i18n の翻訳単位と変数差し込みを維持しながら、装飾の構造を型付きの描画へ置き換える。テキストを部品側へ複製しない                         |
| `Base.tsx` の構造化データ出力                                                                           | 本文の HTML と混同せず、JSON-LD の安全なシリアライズと公開時の検証を維持する                                                            |
| `src/styles/` の Tailwind と中央トークン                                                                | すでに共通の CSS 入口がある。独立した旧スタイル一式が残っている前提で再移行しない                                                       |

HTML / SVG の生成構造を変える後続作業は、生成物のハッシュ差分と同じブラウザでの PC・モバイル表示比較を組み合わせて検証する。今回の移行では生成構造を変えないため、全生成物のバイト一致を条件とする。

フォント設定の保持範囲と外側クリックの挙動は #58・#59 に先立って設計する。公開ページの JavaScript 0 バイトの方針を、このツール移行を理由に変更しない。必要な例外が判明した場合は、具体的な操作仕様と代案を揃えて判断する。

## 検証方針

既存の価格モデル 9 件に比較先月額の欠落 1 件を加え、正常な入力で出す JSON レポートの移行前後の完全一致を確認する。JavaScript ファイルを置いた場合の構造検査の失敗と、誤ったモデル入力の型検査の失敗も確認する。

型・lint・単体テスト・ビルド・静的検査・ブラウザ実測と、公開用生成物全ファイルの SHA-256 一致を確認する。実行結果と残課題の状態は [status.md](../status.md) に記録する。
