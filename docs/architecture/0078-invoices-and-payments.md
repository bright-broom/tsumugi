# 0078 請求書と入金を社内 CLI で記録する

- 日付：2026-09-19
- 状態：採用（main 反映は status.md 参照）

## 背景

監査 D05。見積の支払予定はあるが、請求書の発行・入金・未回収の管理がなく、受注しても請求できなかった。見積書の発行者欄も屋号だけで、氏名・所在地・連絡先がなかった（D04 の一部）。オーナーは 2026-09-19 に、会計サービスではなく社内 CLI で請求と入金を管理すること、適格請求書発行事業者の登録はしていないことを決めた。規約で決まっているのは「制作費は着手時50%・検収時50%」「銀行振込が基本」で、支払期限の日数・振込手数料の負担は定めていない。

## 判断

`npm run ops:invoice`（`tools/ops/billing/`）を追加する。

- 金額は保存済みの見積の版の「支払いの回」からだけ取り、手入力を受け付けない。案件に紐付いた版、見積の顧客・案件が一致するもの、確定額（目安を含まない）に限る。0円は発行しない。
- 発行の時期は契約と案件の状態で止める。着手時・オプション・継続支援は締結済み契約と契約済み以降、検収時は検収済み以降。着手時と検収時は同じ見積の版に限る。継続支援は対象月ごとに1件。
- 請求番号は全顧客で月ごとの通し番号。二重発行を止め、訂正は取消してから再発行し、番号は欠番として残す。入金のある請求書は取消できない。
- 発行者は公開サイトと同じ正本（`src/content/config.ts`）、振込先と登録状況は git 管理外の `billing/profile.json` から読み、発行時の値を請求書に写す。
- 未登録では登録番号を載せず「本書は適格請求書ではありません」と明記する。登録済みに変えた場合は登録番号と税率ごとの消費税を載せる。
- 入金は根拠付きで記録し、残額を超える入金は記録しない。`receivables` は全顧客の未回収を期限順に出し、期限超過で終了コード 1。
- 見積書の発行者欄も同じ正本から屋号・氏名・所在地・電話・メールを出す。

支払期限は規約に定めがないため既定値を作らず、発行ごとに指定させる。送信・決済・会計連携・電子帳簿保存の要件対応はしない。

## 限界

- 免税事業者が消費税相当額をどう表示・請求するかは税務の判断で、このツールでは決めない。現在は公開料金と同じく税別額＋10%で計算する。税理士に確認する。
- 返金・差額精算・充当（規約の増築充当を含む）の記録、会計ソフトへの出力、電子取引データの保存要件は未対応。
- 他の社内 CLI と同じく、利用者の認証・権限はない（オーナーのローカル環境で使う）。
