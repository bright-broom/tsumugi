# 0065 無償修補と変更枠の作業時間を分ける

- 日付：2026-09-18
- 状態：採用（ブランチで実装。main 反映は status.md 参照）

## 背景

監査 D03。ビジネスガイドラインの継続支援条件は「紬側の仕様不適合の修補は月次の変更枠から引かない」。従来の requests は全作業を合算し、月次報告で変更枠超過と案内していた。

## 判断

記録単位に `kind: change | warranty` を追加する。同じ依頼に通常変更と無償修補が混在できる。新規記録では区分を必須にし、warranty には仕様不適合の説明を note に要求する。区分は担当者の判断で、ツールが契約適合性を自動判定するわけではない。

実作業 rawMinutes は全記録の合計。changeMinutes / warrantyMinutes / unclassifiedMinutes を別に持つ。billedMinutes は請求額ではなく、通常変更を月単位で 5 分に切り上げた枠消費分数。修補は消費しない。CLI と Markdown / HTML の月次下書きは同じ集計を利用する。

旧データに kind を補完しない。未分類がある月の billedMinutes は null とし、確定した消費・残り・超過を出さない。3 か月平均は全月が月初から記録済みで、未分類がない場合だけ算出する。記録開始が月途中の場合も月全体の残り・超過を確定しない。

## 互換性と制約

旧 JSON は読み込み可能で、既存時間・日付を自動更新しない。一方、新規 log 呼び出しには kind が必要になる。旧形式の集計は未分類として確認を促すので、以前の数値を確定値として出し続ける互換性は意図的に捨てる。手動の分類手順は [社内ツール手順](../../tools/ops/README.md) に記す。自動訂正・訂正履歴・請求機能は今回追加しない。

価格・契約条件・公開 UI は変更しない。出力 HTML の差分が works.html だけなら、同一コミットかつクリーンな検証証跡の表示条件によるものとしてハッシュで確認する。見積の商品提供可否 C03 は独立課題であり、今回の工数修正で解決したとは扱わない。

## 検証

通常変更と修補の混在、依頼横断の月合計丸め、翌月除外、修補のみの消費 0、3 か月平均、区分・修補根拠の不足、旧 JSON の保持と未確定表示、CLI の保存失敗時無変更、実ファイルの保存と再読込、月次 Markdown / HTML の表示・超過抑止を回帰検査する。全体検査の結果と証跡は [status.md](../status.md) に記録する。
