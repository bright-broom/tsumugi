# 0086 メニューはブラウザ標準の popover で開閉し、閲覧者の書体切替は見送る

- 日付：2026-09-26
- 状態：採用（実機の Safari・支援技術での確認は未実施）

## 背景

#55 の計画で、表示の操作について 2 つの要望が残っていた。どちらも「公開ページの実行時 JavaScript 0 バイト」（[ADR 0001](0001-pages-router.md)、AGENTS.md「崩してはいけないこと」）と両立できるかを先に決める、とされていた（#56 の完了条件）。

- **#59 メニューの外側クリック**：ヘッダーのメニューは `<details>` で、開くと「閉じる」を押すまで閉じない。外側の空白・リンク・ボタンを押したら閉じ、しかもそのリンクやボタンも同じ 1 回で動いてほしい。Esc でも閉じ、フォーカスをボタンへ戻す。
- **#58 書体の切替**：閲覧者が表示設定から Noto Sans JP・明朝・游ゴシックを選べるようにする。

## 判断

### メニュー：`popover="auto"` にする（#59）

HTML の popover 属性は、ブラウザ自身が次を行う。JavaScript を 1 行も書かずに #59 の条件がそろう。

| 条件                                  | popover="auto" の標準の動き                                                              |
| ------------------------------------- | ---------------------------------------------------------------------------------------- |
| 外側の空白で閉じる                    | light dismiss。押した場所がパネルとボタンの外なら閉じる                                  |
| 外側のリンク・ボタンが同じ 1 回で動く | 閉じる処理はクリックを取り消さない（透明な全面の覆いを置かない）。押した先はそのまま動く |
| Esc で閉じ、フォーカスをボタンへ戻す  | 標準で行う                                                                               |
| ボタンをもう一度押すと閉じる          | `popovertarget` の既定は toggle                                                          |
| 開閉の状態を支援技術に伝える          | `popovertarget` を持つ button に展開状態が対応づく                                       |

- `Header.tsx`：`<details><summary>` を、`<button popovertarget="site-menu">` と `<div id="site-menu" popover="auto">` に置き換えた。見た目の状態（「閉じる」の表示・×の形）は `.menu:has(.menu-panel:popover-open)` で切り替える。
- パネルは最前面（top layer）に出るので、ブラウザ既定の中央寄せを外し、ヘッダーの直下・右端に固定する（PC は `--spacing-header-pc`、モバイルは `--spacing-header-mb` の高さ）。
- **popover に対応しないブラウザ**（Safari 17・Firefox 125・Chrome 114 より前）では、`@supports not selector(:popover-open)` でメニューのボタンとパネルを出さない。全ページへの案内はフッターにあり、PC ではヘッダーの主要な案内も残る。パネルが本文の途中にむき出しで出るよりよい。
- 本物のモーダル（確認ダイアログなど、背後を操作させないもの）が将来必要になったら、`<dialog>` の `showModal()` を使い分ける。こちらは外側の操作を遮るので、メニューには使わない。

### 書体の切替：実装しない（#58）

実行時 JavaScript 0 バイトのままでは、**選んだ書体をページ移動・再読み込みの後まで保てない**。保存先（Cookie・localStorage）に書くには JavaScript か、サーバー側の処理が要る。静的に書き出したサイトには後者もない。

- CSS の `:has(input:checked)` を使えばそのページの中だけは切り替えられるが、リンクを 1 回押すと元に戻る。「表示設定」としては期待外れで、かえって混乱させる。
- 候補の Noto Sans JP を確実に出すには Web フォントの配信が要る。日本語の書体は数 MB あり、現在の「外部フォントなし」「LCP を測って載せる」方針と引き換えになる。
- 読みやすさの要望は、ブラウザと OS の文字の大きさ・書体の設定、リーダー表示で閲覧者自身が変えられる。サイトは `rem` と中央のトークンで大きさを決めているので、これらの設定に追従する（最小の文字は 14px、#57）。

したがって #58 は「見送り」とする。**JavaScript の例外を認める判断をオーナーが下したとき**に再開する。そのときは、保存先・読み込み量・レイアウトの揺れ・支援技術での選択状態を、この ADR を置き換える新しい ADR で決める。

## 限界

- 実機の Safari（iOS・macOS）と支援技術（VoiceOver・NVDA）での読み上げは未確認。確認は Chromium（Playwright）だけ。
- `popovertarget` は React の属性名のまま `popoverTarget` で出力される。HTML の属性名は大文字小文字を区別しないので、ブラウザは同じものとして扱う（parse5 での解析で確認）。

## 検証

- `tests/header-menu.test.tsx`：popover のボタンとパネルが対応していること、`popover="auto"`、`<details>` に戻っていないこと、script とイベント属性がないこと、パネルに主要な案内があること。変更前の `<details>` では失敗する。
- JavaScript を無効にした Chromium で、PC 1440px とモバイル 390px を各 14 項目、計 **28 項目すべて合格**：開く・ヘッダー直下で画面内に出る・「閉じる」の表示・外側の空白で閉じる・パネル外の実際の位置で押したリンクが 1 回で遷移する・Enter で開く・Tab でパネル内へ移る・Esc で閉じる・Esc 後にボタンへフォーカスが戻る・ボタンの再押下で閉じる・パネル内のリンクで遷移する・button として読まれる。
- 閉じた状態の見た目は、`design:compare` で全 22 ページ × 4 幅（320・390・768・1440px）の **88 画面が変更前と完全に一致**。開いたときのボタンの位置・大きさ・文字の大きさ・行の高さも変更前と一致（最初の実装では `font: inherit` が文字の大きさを 16px に戻していたので直した）。
