# 0027 — 「ソースコードも公開」の説明を、公開リポジトリと顧客への納品に分けて書く

日付：2026-09-16。状態：採用。関連：[#40](https://github.com/bright-broom/tsumugi/issues/40)。

## 背景

- `works.html` は「ソースコードも公開しており、実装と検査の方法を確認できます」と書いていたが、閲覧先のリンクがなかった。
- #40 は監査時点（2026-09-14、リポジトリは private）の状態をもとに「非公開の本体リポジトリは維持する」を完了条件にしていた。その後、オーナーは同日に `bright-broom/tsumugi` を **Public のままにする**と明示的に承認し（AGENTS.md「進め方」、`docs/business/` の社内資料を含む push を承認）、現在は Public。
- `source.html` などが説明する「GitHub に閲覧権限でご招待」は、顧客サイトの納品の話で、自社サイトの公開とは別。二つが同じ言葉で書かれ、読み手が区別しにくかった。

## 決定

- #40 の「非公開を維持」は、その後のオーナーの判断で置き換わったものとして扱う。公開用サンプルを別に作らず、実在する公開リポジトリを案内する。
- 公開先は `src/content/config.ts` の `SOURCE_REPOSITORY_URL`（`https://github.com/bright-broom/tsumugi`）に置く。ページはこの値からリンクする。非公開に戻すときは `null` にすれば、`works`・`spec` は「現在公開していません」に切り替わる。
- `works.html` の説明を 2 つに分ける。
  - 一般の方が見られるもの：このサイト（紬の自社サイト）のソースコードと検査スクリプト。公開リポジトリ（GitHub）へのリンク。
  - 契約したお客様への納品：お客様のサイトのソースコードは一般に公開せず、契約したお客様を閲覧権限で招待して渡す。`source.html`（納品する内容）へのリンク。
- `spec.html` の「実装と検査結果を照らし合わせて確認できるよう公開しています」も、何を・どこで公開しているかを書き、同じ設定からリンクする。

## 注意

- 公開リポジトリには `docs/business/` の社内資料も含まれる（オーナー承認済み）。公開範囲を変える判断はオーナーが行い、変えたら `SOURCE_REPOSITORY_URL` とこの ADR を更新する。
- リポジトリの公開状態は、外部に通信しない `verify` では確かめられない。本番公開の前にオーナーが確認する。
- 顧客サイトのテンプレートとして使うときは、`SOURCE_REPOSITORY_URL` を顧客の方針に合わせて `null` にするか差し替える。

## 検証

- `works.html` に公開リポジトリと `source.html` へのリンクが出て、内部リンクの検査が通ること（外部リンクは対象外）。
- 全ページの描画テスト（和欧文の間隔、区切りコメントなし）が通ること。出力の差分は `works.html`・`spec.html` だけ。
