# 0044 — 独自ドメインでの公開後の確認をコマンドにする

日付：2026-09-16。状態：採用。関連：[#14](https://github.com/bright-broom/tsumugi/issues/14)、[#13](https://github.com/bright-broom/tsumugi/issues/13)、[ADR 0046](0046-post-launch-monitoring.md)。

## 背景

`npm run verify` は `out/`（納品物）を検査する。独自ドメインで配信したあとに起きる問題、つまり DNS の設定漏れ、証明書の未発行、ホスティング側での転送や script の挿入、`DOMAIN` を差し替え忘れたビルドの配備、存在しない URL が 200 を返す設定は、`out/` を見ても分からない。これまで公開後の確認は手作業の予定で、手順も記録欄もなかった。

ドメインの取得・DNS・Vercel のドメイン設定はオーナーのアカウントでの外部作業で、このリポジトリからは実施も確認もできない。実在する本番 URL もまだない。

## 決定

`npm run check:live -- --url https://<ドメイン>` を追加し、配信されたものを外から確かめる。

| 項目 | FAIL の条件 |
|---|---|
| DNS の解決 | アドレスが返らない |
| HTTPS の証明書 | 信頼できる発行元で検証できない・ホスト名が一致しない・残り 7 日未満（21 日未満は WARN） |
| HTTP から HTTPS への転送 | `http://` が HTTPS へ転送されない（302/307 の一時転送は WARN） |
| トップページ | `/` が 200 でない |
| robots.txt | 200 でない、`User-agent: *` に `Disallow: /`、`Sitemap:` がこのドメインの sitemap を指さない |
| sitemap.xml | 200 でない、`<loc>` がない、ほかのドメインを指す URL がある |
| 掲載 URL の応答 | 1 件でも 200 でない（転送も不可） |
| canonical・og:url | 各ページに 1 個ずつで、掲載 URL と完全に一致しない |
| 実行時 JavaScript | JSON-LD 以外の `<script>` かインラインのイベント属性がある |
| 存在しない URL | 404 を返さない |

加えて、`src/content/config.ts` の `DOMAIN` が指定ドメインと違えば WARN を出す（差し替え忘れの早期発見）。

- **検査の本体はネットワークに直接触らない。** `tools/ops/probe.ts` の `Probe`（HTTP 取得・名前解決・証明書の読み取り）だけを使い、テストでは `fetch` を `Response` を返す関数に差し替える。CI の単体テストは通信しない。
- **公開前のリハーサル**として `--dist out` を用意する。`out/` を静的ホスティングと同じ規則（`/` は `index.html`、無いファイルは `404.html` を 404）で返す模擬配信で、DNS・証明書・HTTP 転送は SKIP と明示する。ソケットを開かないので、待ち受けが禁止された環境でも動く。
- HTML は正規表現ではなく parse5（既存の依存）で読む。依存の追加はない。
- 結果は標準出力と `.artifacts/ops/check-live.json`（Git 管理外）に残す。GitHub Actions で動かした場合はジョブの要約にも表を書く。
- `tools/verify/` とは独立に `tools/ops/` に置く。`verify` の改修（#13・#34）と衝突させないため。

証明書の日数は運用上のしきい値で、測定値ではない。発行元の自動更新が止まった兆候を、期限切れの 1 週間以上前に知るために置く。

## 検証の範囲

- 単体テストで、正常なサイト、ほかのドメインを指す canonical・og:url、挿入された script とイベント属性、ソフト 404、500 と転送、robots の全体拒否、証明書の期限・検証エラー、HTTP のまま、名前解決の失敗、URL 指定の誤り、模擬配信の外への読み出しを確認した。
- 作業環境（サンドボックス）では TCP の待ち受けと外部への接続を試験に使えないため、実ネットワーク経由の `fetch`・DNS・TLS の経路は未実行。ビルドした `out/` へのリハーサル（`--dist out`）で、HTTP 取得以降の判定を実データで確かめた。**実 URL での初回実行は公開作業の一部としてオーナーが行う。**

## 今回の境界

ドメインの取得、DNS、証明書、Vercel のドメイン設定、本番配備、公開承認は実施していない。手順と記録欄は [operations.md「独自ドメインで本番公開する」](../operations.md) に置き、結果は空欄のまま残す。
