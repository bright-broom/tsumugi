# 0081 言語をビルドごとに選び、追加言語を /<言語>/ 配下に公開する

- 日付：2026-09-19
- 状態：採用（実際の翻訳での表示確認は未実施。main 反映は status.md 参照）

## 背景

監査 C02・オプション「多言語対応 1言語（最大6ページ、支給翻訳の組込み・確認1回）」。文言は i18n カタログに集約済みだが、`getMessages` は日本語以外を拒否し、パス・canonical・OGP・サイトマップ・`<html lang>`・納品検査（verify）は日本語 1 言語を前提にしていた。カタログの型は日本語の文字列そのもの（リテラル型）で、翻訳を書くと型検査に通らなかった。2026-09-19、オーナーは多言語も実装するよう指示した。

## 判断

- **1 ビルド 1 言語**：`SITE_LOCALE`（`src/lib/locale.ts`）でビルドの言語を選ぶ。既定言語はサイトの起点、追加言語は `/<言語>/` 配下。ルート一覧のパス・canonical・生成ページのパスが言語のパスを含む。実行時 JS 0 と Pages Router の静的出力を保つ。
- **ビルドの統合**：`build-locales` が追加言語を `NEXT_DIST_DIR` の別の出力先でビルドし、postbuild を通してから HTML を `out/<言語>/` へ統合する。テーマ・画像・フォントは共有し、共有カードは `public/og/<言語>/`。
- **翻訳の型と突き合わせ**：翻訳は形だけを揃える型 `Translation` で書き、`translated()` で登録するときに日本語と比べ、キー・リストの長さ・差し込み値・`@route:` の違いでビルドを止める。日本語側の差し込み値の型検査はそのまま。翻訳のない言語は日本語で代用せずに止める。
- **相互参照と切り替え**：2 言語以上のときだけ、hreflang（全言語と x-default）とフッターの言語の切り替えを出す。1 言語のサイトの出力は変わらない。
- **検査**：`check-locales` が全言語の lang・canonical・og:locale・共有カードの実在・相互の hreflang と対応ページ・同じ言語内のリンク・言語の切り替え・日本語の混入・サイトマップを検査する。`verify` は言語ごとに実行し（`verify:locales`）、ページは言語のディレクトリ、共有の資産はサイトの起点から探す。日本語の文言そのものを照合する検査（主張の一貫性・他社比較の出典・「円」付きの価格）は他言語では「対象外」と記録し、金額の数字は照合する。結果は言語ごとのファイルに書き、`works.html` が読む既定言語の結果を上書きしない。
- **承認は言語ごと**：公開判断（`OWNER_PUBLICATIONS`）と法務文面の承認（`LEGAL_APPROVALS_BY_LOCALE`）は言語ごとに記録する。翻訳した文面に日本語の承認を流用しない。

URL は同じドメインの `/en/` 配下にする（証明書・ドメインを増やさず、hreflang を素直に書けるため）。

## 限界

- 実際の英訳・英語の共有カードでの表示確認は未実施（この作業環境ではブラウザの起動がサンドボックスで禁止）。オプションの受付準備中は変えていない。
- 一部のページだけを訳す構成は未対応（全ページを同じ構成で出す。オプションの対象である最大 6 ページのサイトはこれで足りる）。
- 開発サーバーは既定言語だけを配る。
