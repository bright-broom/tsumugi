# 0061 — ヒーロー SVG の比率と表示サイズを設計し直す

日付：2026-09-17。状態：採用。

## 決定

ADR 0060 の上端揃えだけでは、幅の広い PC で画像が拡大され、島や人物の下部が切れていた。SVG と表示枠の比率を分けて扱い、PC は全体の構図、モバイルは人物の見やすさを優先する。

- SVG の描画キャンバスを **1920 × 960（2:1）** に変更。元の WebP はそのまま内包し、`xMaxYMin meet` で縦横比を保って右に配置する。新しい左余白と画像の左右端は透過マスクでサイトの背景色になじませる。人物や島は描き直さない。
- 表示領域を最大幅 1920 px で中央配置し、高さは `clamp(380px, 50cqw, 720px)`。PC は高さ 100%・幅 auto で画像の比率を保ち、上下を切らず、横長画面でも画像を過剰に拡大しない。文字の拡大で高さが増えた場合も画像が全高を覆う。
- 768 px 以下は `cover` と `78% 0%` で左右を切る。境界の 768 / 769 px ではキャンバスと領域の比率が同じため、構図は飛ばない。
- コピーと高さを決める疑似要素は同じグリッドに置き、文字が大きくなれば表示領域が伸びる。茶色の帯へコピーを押し出す配置に戻さない。
- 画像の寸法は `HOME_HERO`、表示の CSS は `home.css` に集約。`responsive.css` と `home.css` の重複したヒーロー指定を解消する。i18n のコピーは維持する。

## 採用と確認

共通 frontend-design ガイド 1.0 に従い、既存 React 19.3.0 / Next.js 16.3.5 Pages Router / Tailwind 4.3.3 と SVG の標準機能で実装した。新規依存・外部素材はない。描画キャンバスの寸法変更は元画像の高解像度化ではなく、WebP の画素・SHA-256・容量は維持する。

検証ログ・画像は `.artifacts/hero-canvas/` に保存。幅 320 / 390 / 768 / 769 / 1024 / 1440 / 1920 / 2560 px とコピーの 200% 拡大、計 16 条件を Chromium で検証し、画像の配置、ヘッダーとの位置関係、コピーの収まり、横はみ出しなしを確認した。拡大検証はコピーの計算済み文字サイズを 2 倍にする模擬確認で、ブラウザ全体のズーム・実機検証とは区別する。

`validate` 合格（型・lint・Vitest 518 件・料金モデル 12 件・ビルド・セキュリティ・静的検査）。最終 CSS のビルド後も本番モード全項目 PASS 581 / WARN 3 / FAIL 0、21 ページすべて実行時 JS 0。WARN は既存の専門家・受入確認の未実施。SVG は 650,077 → 650,458 bytes（マスク追加分 381 bytes）で、軽量化や画質向上の主張はしない。

法令・料金・公開条件は変更しない。本番反映と実機 Safari の確認は別途扱う。
