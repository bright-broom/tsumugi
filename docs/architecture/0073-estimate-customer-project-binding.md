# 0073 — 見積の顧客・案件を固定し、CRMへの紐付けを照合する

日付：2026-09-18。状態：採用。関連：#27、監査D04。

## 問題

見積は宛名だけを持ち、CRMは番号・版を入力するだけで紐付けできた。存在しない版や別顧客・別案件の見積を記録でき、改版時にも帰属を確認していなかった。

## 決定

- 新しく保存する見積条件にはcustomerIdとprojectIdを必須とする。宛名は表示用で、同じ名前からIDを推定しない。試算はIDなしでも可能。
- 同じ見積番号の全版で、顧客・案件・内部の見積番号の一致を検査する。別の帰属への付け替えは拒否する。
- CRMの紐付け時に同じ保存先の実ファイルを読み、ファイル名・内外の見積番号・要求した版・顧客・案件を照合。失敗時は顧客ファイルを書き換えない。PR #86の共通ロック内で読み込みから保存まで行う。
- 旧見積は読み込み・比較・書面出力の互換性を保つ。帰属のない旧版への追記・新しいCRM紐付けは拒否し、担当者が内容を確認して新しい見積番号で保存する。既存データは自動移行しない。

## 残ること

これは利用者認証や権限管理ではない。保存時にCRM登録の存在を必須とはせず、実在案件との照合はCRMへの紐付け時に行う。旧CRMの参照は自動修正せず、既存の状態遷移にも今回の照合を遡及しない。契約との対応、外部実費、充当、発行者情報、実際の送付先の確認はD04として残す。顧客向けの一括出力は引き続き見積の参照だけで、本文を自動同梱しない。

## 検証

旧版の読み込みと保存拒否、帰属変更拒否、同一帰属の改版、別プロセスのCRMで不存在・版違い・顧客違い・案件違い・旧版・番号違いを拒否し保存前後の内容不変、正常な紐付けを確認。全体検証の結果はstatus.mdを参照。
