### 仕様20項目の確かめ方

`spec.html` の20項目は、すべてを自動検査で証明できるわけではない。項目ごとの方法は `tools/verify/acceptance.ts` の対応表が正本で、ページにも同じ方法を表示する。

- 自動検査だけ：13 表示速度、14 先頭画像
- 自動検査と人の確認：1 電話、2 営業時間、3 住所・地図、4 料金、5 電話とフォームの主役、7 写真、12 スマホとPCの内容、15 スコアを追わない、16 タップ領域、17 構造化データ
- 人の確認：6 対応エリア、8 スタッフ紹介、9 実績、10 お客様の声、11 料金・選び方の説明
- 外部サービスでの確認：18 Googleビジネスプロフィール、19 通知2系統、20 口コミの運用

人の確認・外部接続の確認は `src/content/acceptance.ts` に記録し、本番モードでは記録の無い項目を FAIL にする。レポートの `acceptance` に項目ごとの状況が残る。

### 検証で実際に見つかった不具合

この仕組みを作った初回で、**目視では気づきにくい3件**が出ました。

1. **ヘッダーの電話番号が赤地に赤で描画されていた。**
   `.tel .num` が、表のバツ印用に定義した `.no{color: 琥珀}` を拾っていたCSSのカスケード衝突。
   → コントラスト検査に `.tel .num` を追加して、機械で捕まえられるようにしました。
2. **13ページで `<h1>` が0個だった。**
   セクション見出しが全部 `<h2>` だったため。
   → ページの先頭の見出しを `h1` にすることを不変条件にして（`<Section h1>`）、`verify` が検査します。
3. **1ページだけタップ領域の判定が誤検出していた。**
   CSS適用前に計測していた競合状態。
   → スタイルシートの適用完了を待ってから計測するようにしました。
4. **図の琥珀色の注記が、エスプレッソ紺の節の上で 2.94:1 しか出ていなかった。**
   SVGの `<text>` は `fill` で色が決まるため、本文用のコントラスト検査を素通りしていました。
   → 図専用の検査を足し、`section.dark .fig` でトークンを明るい側に振り替えました。
